Les quatre décisions de cet exercice

1 · Pourquoi class partout, sauf pour le contact

Six accroches sur sept sont des classes. Le bloc de contact est le seul id, et pour une raison précise : il est unique et destiné à servir de cible à un lien interne (href="#contact", projet 1).

La règle pratique : class pour styler, id pour désigner. Un id ne touche qu'un élément — le jour où le même style doit resservir, tout est à refaire.

2 · Pourquoi .formule une fois pour trois articles

Les trois formules partagent la même classe, donc une seule règle les habille toutes. Avec trois id différents, il aurait fallu écrire trois fois le même bloc — et le modifier trois fois à chaque changement.

3 · Pourquoi le <div class="rangee"> reste un <div>

Cette boîte n'existe que pour aligner les formules côte à côte. C'est un groupement purement visuel, sans contenu propre ni titre.

Y mettre <section> annoncerait au lecteur d'écran une partie thématique qui n'existe pas. C'est le principe vu au projet 2 : une balise sémantique posée à tort est pire qu'un <div> neutre.

4 · Pourquoi banniere et non bandeau-bleu

On nomme le rôle, pas l'apparence. Le jour où la charte graphique passe au vert, .bandeau-bleu { background: green; } devient absurde — et présent dans cinquante fichiers. .banniere reste juste quelle que soit la couleur.

Les erreurs fréquentes

Symptôme Cause probable
Une règle ne s'applique pas, sans message d'erreur Le nom diffère entre le HTML et le CSS — une faute de frappe, un accent, une majuscule. C'est l'erreur n°1
Rien ne change alors que le code semble juste Un des deux fichiers n'est pas enregistré. Le point à côté du nom de l'onglet VSCode le signale
La carte « Famille » ressemble aux autres Les deux classes ne sont pas séparées par une espace, ou la seconde manque
Le bloc contact n'a aucun style Le CSS utilise un point (.contact) au lieu d'un dièse (#contact)
Les formules restent empilées display: flex est sur .formule au lieu de .rangee — la règle va sur le parent
Les prix ne changent pas La classe prix existait déjà : inutile de la créer, il fallait seulement écrire la règle

Le réflexe qui diagnostique en trois secondes : clic droit sur l'élément récalcitrant → Inspecter. Si le panneau des styles est vide, aucune règle ne le vise — le nom ne correspond pas. Si la règle apparaît barrée, elle est écrasée par une autre.

🎉 Fin du projet 3

Vous savez désormais habiller une page : écrire des règles, maîtriser les espacements, disposer des éléments côte à côte, et créer vos propres points d'accroche quand le HTML n'en offre pas.
