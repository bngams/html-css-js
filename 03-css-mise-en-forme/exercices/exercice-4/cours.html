Projet 3 · Exercice 4

Poser ses propres accroches

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : ajouter vous-même des class et des id dans le HTML, pour pouvoir viser exactement ce que vous voulez en CSS.

C'est le dernier exercice du projet — et le seul où vous modifiez les deux fichiers.

1 · Pourquoi on en arrive là

Dans les trois exercices précédents, le HTML était figé et déjà pourvu de classes. Vous n'aviez qu'à les viser. Mais posez-vous la question : que faire si l'accroche dont vous avez besoin n'existe pas ?

Prenons une page réelle :

<p>Un paragraphe ordinaire.</p>
<p>Celui-ci doit être en rouge et encadré.</p>
<p>Un autre paragraphe ordinaire.</p>

Comment viser le deuxième seulement ? Le sélecteur p les prendrait tous les trois. Il n'existe aucune classe. Vous êtes bloqué — non par le CSS, mais par le HTML, qui n'offre aucune prise.

La réponse : on ajoute la prise. C'est exactement ainsi qu'on travaille en vrai — le HTML et le CSS s'écrivent ensemble, en aller-retour. Le développeur qui a préparé vos exercices précédents avait posé ces classes pour cette raison.

2 · Ajouter une classe

Une classe est un simple attribut posé sur la balise ouvrante — vous connaissez la syntaxe depuis le projet 1 : 

<p class="avertissement">Celui-ci doit être en rouge et encadré.</p>

Et le CSS peut alors le viser :

.avertissement {
  color: #842029;
  border: 1px solid #842029;
}

Plusieurs classes sur un même élément

Un élément peut en porter plusieurs, séparées par une espace : 

<div class="carte carte--large">…</div>

Il reçoit alors les deux règles. Vous l'avez déjà vu à l'exercice 2 : une classe de base, puis une classe de variante qui ne change que le nécessaire.

L'espace sépare deux classes, il n'en crée pas une seule. class="carte large" pose deux classes. Pour une classe dont le nom fait deux mots, utilisez un tiret : class="carte-large".

3 · Bien nommer ses classes

C'est une compétence à part entière. Trois règles suffisent :

Règle ❌ Évitez ✅ Préférez
Nommer le rôle, pas l'apparence rouge, gros-texte alerte, titre-section
Sans accent ni espace en-tête, ma classe en-tete, ma-classe
En minuscules, mots séparés par un tiret MaClasse, ma_classe ma-classe

Pourquoi le rôle plutôt que l'apparence ? Imaginez une classe nommée rouge. Six mois plus tard, la charte graphique change et les alertes deviennent oranges. Vous vous retrouvez avec .rouge { color: orange; } — absurde, et présent dans cinquante fichiers. Une classe alerte reste juste quelle que soit la couleur.

4 · Quand utiliser un id plutôt qu'une classe

Vous connaissez les deux depuis les projets 1 et 2. Le partage des rôles :

class id
Combien par page Autant qu'on veut Un seul — le nom est unique
Sélecteur CSS .nom #nom
Usage principal Le style Les liens internes, le JavaScript

Pour styler, préférez presque toujours la classe. Un id ne peut toucher qu'un élément : le jour où le même style doit servir ailleurs, tout est à refaire. Gardez l'id pour ce qui doit être unique et désigné : une cible de lien interne (projet 1), un champ relié à son étiquette (projet 2), un élément que le JavaScript ira chercher (jour 3).

5 · Choisir la bonne balise, aussi

Ajouter une classe ne dispense pas de choisir la balise juste. Le projet 2 vous l'a appris : <section> pour une partie thématique, <article> pour un contenu autonome, et <div> quand le groupement est purement visuel.

Et c'est précisément le cas quand on crée une accroche pour le CSS. Si vous entourez trois éléments d'une boîte uniquement pour les aligner avec Flexbox, cette boîte n'a aucun sens propre : <div class="rangee"> est le bon choix. Y mettre <section> annoncerait au lecteur d'écran une partie thématique qui n'existe pas.

6 · La méthode, en pratique

L'aller-retour entre les deux fichiers suit toujours le même ordre :

Étape Où
1. Je regarde ce que je veux styler Dans le navigateur
2. Une accroche existe-t-elle déjà ? Dans le HTML
3. Sinon, j'ajoute une classe au rôle bien nommé HTML
4. J'écris la règle qui la vise CSS
5. J'enregistre les deux, je recharge Navigateur

Le piège du jour : vous modifiez deux fichiers, donc il faut enregistrer les deux. Une classe ajoutée en HTML mais non enregistrée, et votre règle CSS ne vise rien — sans aucun message d'erreur. Dans VSCode, un point à côté du nom d'un onglet signale un fichier non enregistré.
