Poser ses propres accroches

🎯 Objectif — Habiller une page qui ne contient presque aucune classe : vous devrez d'abord les créer.

Niveau : débutant. Prérequis : les trois exercices précédents de ce projet.

⚠️ Cet exercice est différent

Vous modifiez LES DEUX fichiers. C'est le seul exercice du projet où le HTML n'est pas figé.

Fichier Ce que vous y faites
travail.html 👉 Vous ajoutez les class et l' id, là où les TODO l'indiquent
style.css 👉 Vous écrivez les règles qui les visent

Pourquoi ce changement ? Dans les trois exercices précédents, les classes vous étaient fournies. Mais en situation réelle, le HTML n'offre pas toujours la prise dont vous avez besoin — alors vous la créez. C'est l'aller-retour permanent du métier.

Le piège du jour : enregistrez les deux fichiers. Une classe ajoutée dans le HTML mais non enregistrée, et votre règle CSS ne visera rien — sans aucun message d'erreur. Dans VSCode, un point à côté du nom d'un onglet signale un fichier non enregistré.

✅ Critères de réussite

Dans travail.html — les accroches à créer

  1. Le <header> porte class="banniere"
  2. Le paragraphe d'introduction porte class="intro"
  3. Le <div> des formules porte class="rangee"
  4. Les trois <article> portent class="formule"
  5. Celui de « Famille » porte en plus formule--conseillee — deux classes séparées par une espace
  6. La <section> de contact porte id="contact"

Dans style.css — les règles à écrire

  1. .banniere — fond #14457b, texte blanc, 30px d'espace intérieur, texte centré
  2. .intro — 1.1rem, couleur #5a6570
  3. .rangee — enfants côte à côte, passage à la ligne autorisé, 20px entre eux
  4. .formule — fond blanc, 20px intérieur, coins arrondis 8px, bordure 1px solid #d7dee8, flex: 1 1 200px, texte centré
  5. .formule--conseillee — bordure 2px solid #0b6bcb, fond #e8f1fb
  6. .prix — 2rem, #14457b, gras, sans marge
  7. #contact — fond blanc, 20px intérieur, coins arrondis 8px, 30px de marge au-dessus

La classe prix existe déjà dans le HTML fourni : vous n'avez pas à la créer, seulement à l'utiliser. C'est le premier réflexe — regarder ce qui est déjà là avant d'ajouter.

Six critères, sept TODO : c'est normal. Le critère 4 (« les trois <article> portent formule ») correspond à deux marqueurs dans le fichier — un pour le premier article, un pour le troisième. Le deuxième est traité à part, puisqu'il reçoit deux classes.

Les ÉTAPE 1 à 7 de travail.html et de style.css portent en revanche les mêmes numéros : c'est sur elles que vous faites l'aller-retour. L'ÉTAPE 6 du HTML ne demande rien — elle vous rappelle que l'accroche existe déjà.

🔍 Comment vérifier

Ce que vous vérifiez Ce que vous devez voir
La bannière Un bandeau bleu foncé pleine largeur, texte blanc centré
Les formules Trois cartes côte à côte dès que la fenêtre est assez large (environ 700 px et plus), blanches, aux coins arrondis. Sur une fenêtre plus étroite, elles passent à la ligne — c'est flex-wrap qui travaille
La formule conseillée Celle du milieu (« Famille ») se distingue : fond bleuté, bordure bleue plus épaisse
Les prix En gros, en bleu foncé — les trois, sans que vous ayez créé la classe
Le bloc contact Une carte blanche détachée, en bas de page

🧪 Manip — le double tiret n'a rien de magique

  1. Dans travail.html, remplacez formule--conseillee par formule-mise-en-avant — sur la balise et dans votre CSS.
  2. Enregistrez les deux, rechargez.

Rien ne change. Le double tiret est une simple convention d'écriture entre développeurs pour signaler une variante : le navigateur y voit un nom comme un autre. Ce qui compte, c'est que le nom soit identique des deux côtés.

Remettez ce que vous préférez — les deux sont corrects.

🧪 Manip — voir l'erreur n°1 se produire

  1. Dans travail.html, modifiez une classe en y glissant une faute : class="formul" au lieu de formule.
  2. Enregistrez, rechargez.
  3. Cette carte perd tout son style. Clic droit dessus → Inspecter : le panneau des styles est vide pour cet élément.

Aucun message d'erreur nulle part — ni dans le HTML, ni dans le CSS. Les deux fichiers sont valides, ils ne se parlent simplement plus. C'est la panne la plus fréquente du métier, et l'inspecteur est ce qui la révèle en trois secondes.

Corrigez la faute avant de continuer.

🏁 Comment savoir que j'ai fini

  • Ctrl+F sur TODO dans les deux fichiers : aucun résultat
  • Les cinq points du tableau de vérification sont constatés
  • Le validateur HTML et le validateur CSS ne signalent aucune erreur

⏱️ Durée indicative

40 à 50 minutes. L'aller-retour entre les deux fichiers demande un peu d'organisation au début : gardez-les côte à côte dans VSCode.
