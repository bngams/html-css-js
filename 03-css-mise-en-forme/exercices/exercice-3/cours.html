Projet 3 · Exercice 3

Disposer avec Flexbox

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : placer des éléments côte à côte — la question qui bloque tous les débutants — puis soigner les finitions : coins arrondis, ombres, dégradés et transitions.

1 · Le problème : tout s'empile

Vous l'avez constaté à l'exercice 2 : vos trois cartes se sont placées les unes sous les autres, occupant chacune toute la largeur. Ce n'est pas un défaut, c'est le comportement par défaut d'un élément de type bloc — div, p, section, h1…

Pendant vingt ans, les mettre côte à côte fut un casse-tête. Depuis Flexbox, c'est une ligne de CSS.

2 · Le principe : un parent, des enfants

Flexbox fonctionne toujours par paire. On déclare display: flex sur un élément — le conteneur — et ce sont ses enfants directs qui se disposent. 

<div class="rangee">        ← le conteneur : on écrit le CSS ICI
  <div class="carte">…</div>   ← les enfants : ils se placent
  <div class="carte">…</div>
</div>
.rangee {
  display: flex;
}

Et voilà : les cartes passent côte à côte.

L'erreur n°1 : écrire display: flex sur les cartes elles-mêmes. Rien ne se passe comme prévu. La règle va toujours sur le parent — celui qui contient les éléments à aligner.

3 · Espacer : gap

Une fois les éléments côte à côte, ils se touchent. gap crée un espace entre eux, sans en ajouter sur les bords : 

.rangee {
  display: flex;
  gap: 20px;
}

gap remplace avantageusement les margin qu'on posait autrefois sur chaque enfant : pas de marge en trop au début ni à la fin, et rien à corriger quand on ajoute un élément.

4 · Répartir sur la ligne : justify-content

Quand les éléments n'occupent pas toute la largeur, cette propriété décide où va l'espace restant :

Valeur Effet
flex-start Tout à gauche (par défaut)
center Groupés au centre
flex-end Tout à droite
space-between Le premier collé à gauche, le dernier à droite, l'espace réparti entre
space-around L'espace réparti autour de chacun

space-between est le choix classique d'une barre de navigation : le logo à gauche, le menu à droite.

5 · Aligner en hauteur : align-items

Quand les éléments n'ont pas la même hauteur, cette propriété décide de leur alignement vertical :

Valeur Effet
stretch Tous étirés à la même hauteur (par défaut)
center Centrés verticalement
flex-start Alignés en haut

Le centrage parfait, celui qui a longtemps fait souffrir : 

.boite {
  display: flex;
  justify-content: center;   /* centré horizontalement */
  align-items: center;       /* centré verticalement */
}

Deux lignes. C'est tout.

6 · Faire passer à la ligne : flex-wrap

Par défaut, Flexbox refuse de passer à la ligne : il comprime les éléments jusqu'à les rendre illisibles. Pour l'autoriser : 

.rangee {
  display: flex;
  flex-wrap: wrap;
  gap: 20px;
}

Les éléments qui ne tiennent plus passent alors à la ligne suivante. C'est le premier pas vers le responsive du projet 4 — une grille de cartes qui devient une colonne sur téléphone, sans une seule ligne de code en plus.

7 · Donner une largeur de base — le raccourci flex

Sur les enfants d'un conteneur flex (et non sur le conteneur, cette fois), une propriété décide de leur largeur : 

.carte {
  flex: 1 1 380px;
    /*  ↑ ↑   ↑
        │ │   la largeur de BASE
        │ peut rétrécir  (1 = oui)
        peut grandir     (1 = oui)  */
}
Valeur Nom Rôle
1re grow L'élément peut grandir pour occuper l'espace libre
2e shrink Il peut rétrécir si la place manque
3e basis Sa largeur de départ

La base n'est pas un minimum — c'est un point de départ. Le navigateur place autant d'éléments qu'il peut à cette largeur, puis répartit l'espace restant entre eux (parce que grow vaut 1).

Conséquence pratique : c'est la base qui décide du nombre d'éléments par ligne. Dans une ligne de 860 px, une base de 380 px en laisse passer deux (380 + 20 + 380 = 780) mais pas trois (1180). Une base de 250 px en aurait laissé passer trois.

Rappel sur rem (projet 3, exercice 2, notion 7) : 1rem vaut la taille de police de base du navigateur, soit 16 px par défaut. Donc 1.3rem ≈ 21 px et 0.9rem ≈ 14 px.

Vous en écrirez deux dans cet exercice. On préfère rem aux pixels pour les tailles de texte : une personne qui a augmenté la police par défaut de son navigateur verra vos textes suivre son réglage.

8 · Les finitions

Coins arrondis

border-radius: 8px;      /* les 4 coins */
border-radius: 50%;      /* un cercle, si l'élément est carré */

Ombres portées

box-shadow: 0 2px 6px rgba(0, 0, 0, 0.12);
         /* décalage-x · décalage-y · flou · couleur */

rgba() ajoute un quatrième nombre à rgb() : l'opacité, entre 0 (invisible) et 1 (opaque). Une ombre réussie est presque toujours du noir très transparent — 0.1 à 0.2. Au-delà, l'effet devient lourd.

Dégradés

background-image: linear-gradient(to right, #0b6bcb, #14457b);

La direction peut être to right, to bottom, to bottom right, ou un angle : 135deg.

Transitions

Sans transition, un changement au survol est brutal. transition l'étale dans le temps : 

.carte {
  background-color: #fff;
  transition: background-color 0.3s;
}

.carte:hover {
  background-color: #e8f1fb;
}

La transition se déclare sur l'état NORMAL, pas sur le survol. C'est l'erreur classique. Posée sur :hover seulement, l'animation ne joue qu'à l'aller — le retour reste brutal.

:hover est une pseudo-classe : elle vise un élément dans un certain état. Vous en croiserez d'autres — :focus (élément sélectionné au clavier), :first-child (le premier de sa fratrie).

N'oubliez pas le clavier. Un effet posé uniquement sur :hover est invisible pour qui navigue au clavier. Sur un élément interactif, écrivez .carte:hover, .carte:focus { … } — les deux états ensemble.
