Afficher app.js en entier 
const emprunts = [
  { livre: "Dune",                  lecteur: "Karim", jours: 21 },
  { livre: "Fondation",             lecteur: "Léa",   jours: 5  },
  { livre: "Les Fourmis",           lecteur: "Tomas", jours: 14 },
  { livre: "Le Nom du vent",        lecteur: "Amina", jours: -3 },
  { livre: "Chroniques martiennes", lecteur: "Léa",   jours: -12 }
];

/* 1 · Les éléments de la page */

const corps    = document.querySelector("tbody");
const form     = document.querySelector("#form-emprunt");
const champL   = document.querySelector("#livre");
const champLec = document.querySelector("#lecteur");
const champJ   = document.querySelector("#jours");
const message  = document.querySelector("#message");
const resume   = document.querySelector("#resume");

/* 2 · Le statut découle des jours restants */

function statutDe(jours) {
  if (jours < 0)  return { texte: "En retard",  classe: "statut--retard" };
  if (jours <= 7) return { texte: "Bientôt dû", classe: "statut--bientot" };
  return { texte: "En cours", classe: "statut--ok" };
}

/* 3 · Fabriquer une ligne du tableau */

function ajouterLigne(emprunt) {

  const tr = document.createElement("tr");

  const tdLivre = document.createElement("td");
  tdLivre.textContent = emprunt.livre;

  const tdLecteur = document.createElement("td");
  tdLecteur.textContent = emprunt.lecteur;

  const tdJours = document.createElement("td");
  tdJours.textContent = emprunt.jours;

  const tdStatut = document.createElement("td");
  const badge = document.createElement("span");
  const statut = statutDe(emprunt.jours);
  badge.textContent = statut.texte;
  badge.classList.add("statut");
  badge.classList.add(statut.classe);
  tdStatut.append(badge);

  tr.append(tdLivre, tdLecteur, tdJours, tdStatut);
  corps.append(tr);
}

/* 4 · Tout redessiner depuis les données */

function afficher() {

  for (const ancienne of corps.querySelectorAll("tr")) {
    ancienne.remove();
  }

  for (const emprunt of emprunts) {
    ajouterLigne(emprunt);
  }

  let enRetard = 0;
  for (const emprunt of emprunts) {
    if (emprunt.jours < 0) {
      enRetard = enRetard + 1;
    }
  }

  resume.textContent = emprunts.length + " emprunt(s) · " + enRetard + " en retard";

  console.log("Tableau :", corps.children.length, "ligne(s) ·", enRetard, "en retard");
}

/* 5 · Au chargement */

afficher();

/* 6 · Le formulaire ajoute un emprunt */

form.addEventListener("submit", function (evenement) {

  evenement.preventDefault();

  const livre   = champL.value.trim();
  const lecteur = champLec.value.trim();
  const saisie  = champJ.value.trim();

  if (livre === "" || lecteur === "" || saisie === "") {
    message.textContent = "Les trois champs sont obligatoires.";
    message.classList.add("erreur");
    console.log("Refusé : un champ est vide");
    return;
  }

  const jours = Number(saisie);

  if (isNaN(jours)) {
    message.textContent = "Les jours restants doivent être un nombre.";
    message.classList.add("erreur");
    console.log("Refusé : jours non numérique");
    return;
  }

  emprunts.push({ livre: livre, lecteur: lecteur, jours: jours });

  afficher();

  message.textContent = "« " + livre + " » ajouté.";
  message.classList.remove("erreur");

  champL.value = "";
  champLec.value = "";
  champJ.value = "";

  console.log("Ajouté :", livre, "→", emprunts.length, "emprunt(s)");
});

Les cinq choses à retenir

1 · Les données sont la vérité

emprunts.push({ … });   ← on modifie LES DONNÉES
afficher();             ← la page se refait toute seule

La page n'est qu'un reflet. On ne la retouche jamais à la main : on change les données, et on redessine. C'est ce qui garantit que le tableau, les statuts et le résumé disent tous la même chose.

C'est le principe de tous les frameworks modernes — React, Vue, Svelte. Vous venez de l'écrire à la main, en quelques lignes.

2 · Une donnée calculée n'est pas stockée

Le statut n'existe nulle part dans emprunts. Il se recalcule à chaque affichage :

joursStatutClasse posée
21En coursstatut--ok
5Bientôt dûstatut--bientot
-3En retardstatut--retard

Pourquoi ne pas le stocker ? Parce qu'il deviendrait faux dès le lendemain. Une donnée qui se déduit d'une autre ne se stocke pas : elle se calcule, au dernier moment.

Et parce que toute la règle tient dans une seule fonction : changer le seuil de 7 à 3 se fait en un caractère.

3 · Les frontières, encore et toujours

jours = -1   → En retard
jours =  0   → Bientôt dû     ⚠️ zéro n'est pas négatif
jours =  7   → Bientôt dû     ⚠️ le ≤ inclut le 7
jours =  8   → En cours

L'ordre des if compte. Le test jours < 0 doit venir en premier : un nombre négatif est aussi <= 7. Inversez les deux lignes, et tous les retards deviennent « Bientôt dû ».

Le résumé, lui, continue d'annoncer 2 en retard — il compte emprunt.jours < 0 directement, sans passer par statutDe(). Cette contradiction entre le résumé et les badges est votre meilleur indice : deux affichages d'une même réalité qui ne disent plus la même chose.

C'est exactement l'ordre des seuils du projet 7, exercice 3.

4 · Un tableau HTML se construit comme une liste

createElement("tr")    ← la ligne      (comme un <li>)
createElement("td")    ← la cellule    (comme un <span>)
tr.append(td1, td2, …) ← on remplit
corps.append(tr)       ← ALORS elle apparaît

Rien de neuf depuis le projet 9, exercice 3. Seuls les noms de balises changent. Un tableau n'est pas un objet spécial : c'est du HTML comme le reste.

On insère dans le <tbody>, jamais dans le <table>. À l'écran, les deux donnent le même résultat — mais un <tr> ajouté sur le <table> laisse le <tbody> vide : le vidage n'efface plus rien, les lignes se dupliquent, et la console annonce 0 ligne(s) en permanence.

5 · Une vérification qui ne sert jamais

const jours = Number(saisie);
if (isNaN(jours)) { … }

Ce test ne se déclenchera quasiment jamais, et c'est mesuré : le champ type="number" refuse déjà les lettres — taper « abc » y produit une chaîne vide, qui part donc dans la branche « champ obligatoire ».

Gardez-le quand même. Changez type="number" en type="text" dans la page, et le message apparaît. C'est exactement ce qui arrive le jour où quelqu'un modifie le formulaire : la vérification coûte deux lignes, et elle est déjà là.

(Coller « abc » dans un champ type="number" ne la déclenche pas non plus : le navigateur rend une chaîne vide. Seul le changement de type l'atteint.)

Les erreurs fréquentes

SymptômeCause
Les lignes s'ajoutent en double à chaque envoi Le tableau n'est pas vidé au début de afficher() (projet 9, exercice 4)
La nouvelle ligne disparaît au prochain ajout Elle a été insérée dans la page sans passer par push : les données l'ignorent, le redessin l'efface
Tous les emprunts en retard affichent « Bientôt dû » Le test jours <= 7 est placé avant jours < 0
Le statut s'affiche mais reste noir La classe statut est posée sans la classe de couleur, ou l'inverse — il en faut deux
La page se recharge à l'envoi, le tableau revient à 5 lignes preventDefault() manque (projet 10, exercice 3)
Le résumé reste bloqué sur l'ancien compte Il est calculé une seule fois au chargement, hors de afficher()

🎁 Le bonus, une piste

Une façon d'aller chercher cinq lecteurs et d'en faire des emprunts : 

fetch("https://dummyjson.com/users?limit=5")
  .then(function (reponse) {
    return reponse.json();
  })
  .then(function (donnees) {

    for (const utilisateur of donnees.users) {
      emprunts.push({
        livre:   "À définir",
        lecteur: utilisateur.firstName,
        jours:   utilisateur.id * 3 - 5      ← dérivé d'un champ de l'API
      });
    }

    afficher();        ← indispensable : les données ont changé
  })
  .catch(function (erreur) {
    console.log("Impossible de charger les lecteurs :", erreur);
  });

Le afficher() à l'intérieur du second .then n'est pas optionnel. Les données arrivent après que la page a été dessinée une première fois. Sans ce second appel, elles restent invisibles.

Et le .catch non plus. Une requête réseau peut échouer — pas de connexion, serveur indisponible. Sans lui, l'erreur passe inaperçue.

Pourquoi id * 3 - 5 plutôt qu'un nombre fixe ? Parce qu'une durée identique pour tous donnerait cinq lignes du même statut. En la dérivant d'un champ de l'API, on obtient les trois statuts : 

Emily   (id 1)  →  -2 jours  →  En retard
Michael (id 2)  →   1 jour   →  Bientôt dû
Sophia  (id 3)  →   4 jours  →  Bientôt dû
James   (id 4)  →   7 jours  →  Bientôt dû   ← pile sur la frontière
Emma    (id 5)  →  10 jours  →  En cours

Dériver une donnée d'une autre est exactement le geste du statut : c'est le métier de qui consomme une API.
