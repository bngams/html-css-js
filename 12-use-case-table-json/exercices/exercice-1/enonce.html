Le registre des emprunts

  • ✍️ À vous de jouer

🎯 Objectif — Le registre des emprunts de la médiathèque : un tableau alimenté par des données, un formulaire qui l'enrichit, et un statut calculé pour chaque ligne.

Prérequis : tout le parcours. Aucune notion nouvelle, sauf fetch pour le bonus.

🟥 Ce projet n'a pas de squelette.

Aucun fichier JavaScript ne vous est fourni, et travail.html ne charge aucun script. C'est le dernier projet : vous créez votre fichier vous-même, et vous le branchez.

Comment démarrer

  1. Copiez travail.html dans un dossier à vous, sous le nom index.html
  2. Créez à côté un fichier app.js — le nom est libre, mais autant garder celui du parcours
  3. Ajoutez <script src="app.js"></script> juste avant </body> de votre copie
  4. Recopiez les données de départ ci-dessous en haut de votre fichier
  5. Vérifiez tout de suite que le branchement marche : écrivez console.log("branché"); comme seule ligne de app.js, rechargez, et regardez la console. Le message apparaît ? Vous pouvez commencer. Sinon, vérifiez le nom du fichier et sa position, à côté de votre index.html

📦 Les données de départ

const emprunts = [
  { livre: "Dune",                  lecteur: "Karim", jours: 21 },
  { livre: "Fondation",             lecteur: "Léa",   jours: 5  },
  { livre: "Les Fourmis",           lecteur: "Tomas", jours: 14 },
  { livre: "Le Nom du vent",        lecteur: "Amina", jours: -3 },
  { livre: "Chroniques martiennes", lecteur: "Léa",   jours: -12 }
];

jours est le nombre de jours restants avant le retour. Un nombre négatif signifie que l'emprunt est en retard.

✅ Les critères d'acceptation

Au chargement

  1. Le tableau affiche une ligne par emprunt, dans l'ordre des données, avec quatre cellules : livre, lecteur, jours restants, statut
  2. Chaque statut est un <span> portant la classe statut et sa classe de couleur : statut--retard, statut--bientot ou statut--ok
  3. Le statut est calculé, jamais écrit dans les données : jours < 0 → En retard · jours ≤ 7 → Bientôt dû · sinon En cours
  4. Le résumé sous le tableau affiche 5 emprunt(s) · 2 en retard — les deux nombres calculés

Quand on ajoute un emprunt

  1. La page ne se recharge pas, et la nouvelle ligne apparaît en bas du tableau
  2. L'emprunt est ajouté au tableau de données, pas seulement à l'affichage — le résumé et les statuts s'actualisent en conséquence. Pour le vérifier : après deux ajouts, le résumé doit annoncer 7 emprunt(s) et la console → 7 emprunt(s). S'il reste bloqué sur 5, votre ligne est dans la page mais pas dans les données
  3. Les trois champs sont vidés après un ajout réussi, et le message affiche « Livre » ajouté. sans la classe erreur
  4. Le statut de la nouvelle ligne est calculé comme les autres — saisir 3 doit donner Bientôt dû, -4 doit donner En retard

Quand la saisie est incomplète

  1. Si l'un des trois champs au moins est vide, rien n'est ajouté : ni aux données, ni au tableau, et le résumé ne bouge pas
  2. Le message affiche Les trois champs sont obligatoires. et porte la classe erreur. Les champs déjà remplis ne sont pas vidés
  3. Un champ contenant seulement des espaces compte comme vide
  4. Après un refus, un ajout correct enlève la classe erreur

Dans la console

  1. La console affiche, à chaque moment, la ligne attendue :
    • après chaque redessin — Tableau : le nombre de lignes, ligne(s) · le nombre de retards, en retard
    • à chaque ajout — Ajouté : le livre, → le total, emprunt(s)
    • à chaque refus — Refusé : un champ est vide

🔍 Comment vérifier

Rechargez. Avant toute action, la console affiche exactement cette ligne : 

Tableau : 5 ligne(s) · 2 en retard

Ajoutez ensuite Solaris / Amina / 3, puis envoyez avec les trois champs vides, puis ajoutez Ubik / Tomas / -4 avec les espaces. La console doit afficher, à la suite : 

Tableau : 6 ligne(s) · 2 en retard
Ajouté : Solaris → 6 emprunt(s)
Refusé : un champ est vide
Tableau : 7 ligne(s) · 3 en retard
Ajouté : Ubik → 7 emprunt(s)

La ligne Tableau : précède celle de l'ajout. C'est normal : on redessine d'abord, on annonce ensuite. Si l'ordre est inversé chez vous, ce n'est pas une erreur — seuls les critères comptent.

Et le tableau doit ressembler à ceci :

Testez les frontières, c'est là que les erreurs se cachent. Ajoutez un emprunt avec 0 jour, puis un avec 7, puis un avec 8 : 

0 → Bientôt dû   (zéro n'est pas négatif)
7 → Bientôt dû   (le 7 est inclus)
8 → En cours

🧪 Manip — ajouter au tableau sans toucher aux données

Une fois l'exercice terminé, essayez volontairement ceci :

  1. Dans votre gestionnaire de formulaire, remplacez le push + afficher() par un appel direct à votre fonction qui fabrique une ligne.
  2. Enregistrez, rechargez, ajoutez un emprunt : il apparaît. Puis ajoutez-en un second.
  3. Provoquez ensuite un redessin : envoyez le formulaire avec un champ vide ne suffit pas — remettez le push et rechargez, ou appelez afficher() depuis la console.

Les deux lignes s'ajoutent bien — mais regardez le résumé : il reste bloqué sur 5 emprunt(s) · 2 en retard, et la console annonce → 5 emprunt(s) à chaque fois. La page montre sept lignes, les données n'en connaissent que cinq.

Au redessin, vos deux lignes disparaissent d'un coup : le tableau est reconstruit depuis les données, qui ne les ont jamais vues.

Remettez ensuite le push.

🎁 Bonus — les données viennent d'un serveur

Uniquement si le reste fonctionne. Chargez cinq lecteurs depuis https://dummyjson.com/users?limit=5 et ajoutez-les au registre.

L'API rend des utilisateurs, pas des emprunts : à vous de traduire firstName vers lecteur, et d'inventer un livre et un nombre de jours. Le cours §7 montre la forme de fetch.

⚠️ Le bonus exige un serveur local — python3 -m http.server 8000, puis http://localhost:8000. En double-clic, fetch est refusé.

🏁 Comment savoir que j'ai fini

  • Les cinq emprunts s'affichent avec le bon statut et la bonne couleur
  • Le formulaire ajoute une ligne sans recharger la page
  • Une saisie incomplète est refusée, en rouge, sans rien perdre
  • Le résumé est toujours juste
  • Vous savez dire pourquoi on ajoute aux données avant de redessiner

⏱️ Durée indicative

60 à 90 minutes, bonus compris. C'est le projet le plus long, et le seul sans squelette. Procédez par étapes : l'affichage d'abord, le statut ensuite, le formulaire en dernier. Vérifiez après chaque étape.
