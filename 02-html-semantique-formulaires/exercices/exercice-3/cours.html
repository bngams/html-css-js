Les formulaires

Ce que vous allez apprendre ici : recueillir des informations auprès de vos visiteurs — un champ de saisie, une liste de choix, une case à cocher — et le faire correctement.

C'est le dernier chapitre du projet 2, et le plus utile en pratique : presque tout site a un formulaire de contact ou d'inscription.

1 · Le conteneur — <form>

Tous les champs vivent à l'intérieur d'une balise <form> :

<form>
  …les champs…
</form>

Où partent les données ? Un vrai formulaire porte deux attributs — action (l'adresse qui reçoit les données) et method. Les traiter demande un serveur ou du JavaScript : ce sera le jour 3. Ici, on apprend à construire le formulaire ; l'envoi viendra ensuite.

2 · Le champ de base — <input>

Une balise auto-fermante (comme <img>, projet 1). Son attribut type décide de ce qu'elle devient :

type Ce que l'utilisateur voit
text Une ligne de saisie libre
email Idem, mais le navigateur vérifie la présence d'un @
tel Idem — et sur mobile, un clavier numérique s'affiche
number Un champ avec des petites flèches haut/bas
date Un sélecteur de date fourni par le navigateur
checkbox Une case à cocher
radio Un bouton rond — un seul choix possible dans un groupe 
<input type="email" id="courriel" name="courriel">

Choisir le bon type est gratuit et rend service. type="email" ne demande aucun effort de plus que type="text", mais il déclenche une vérification automatique et, sur téléphone, affiche le clavier adapté.

3 · L'étiquette — <label>

Un champ seul est une boîte vide : rien ne dit ce qu'il attend. L'étiquette s'écrit dans un <label>, relié au champ : 

<label for="courriel">Votre e-mail</label>
<input type="email" id="courriel" name="courriel">

Le lien se fait par une paire d'attributs : le for du label reprend exactement l'id du champ. C'est le même mécanisme d'id que pour les liens internes du projet 1 — un nom unique qui permet de désigner un élément.

Une faute de frappe entre les deux casse le lien silencieusement : aucun message d'erreur.

Deux bénéfices immédiats

  • Cliquer sur l'étiquette place le curseur dans le champ. C'est le test le plus simple pour vérifier que le lien fonctionne.
  • Un lecteur d'écran annonce l'étiquette quand l'utilisateur arrive sur le champ. Sans <label>, il annonce « zone de texte », sans dire ce qu'on attend.

Et name, alors ?

id sert à relier le label au champ dans la page. name est le nom sous lequel la valeur sera envoyée au serveur. On met souvent le même mot dans les deux, mais ils ne servent pas à la même chose.

4 · Les autres champs

Une liste déroulante — <select>

<label for="niveau">Votre niveau</label>
<select id="niveau" name="niveau">
  <option value="debutant">Débutant</option>
  <option value="confirme">Confirmé</option>
</select>

Chaque choix est une <option>. L'attribut value est ce qui part au serveur ; le texte entre les balises est ce que voit l'utilisateur.

Un texte long — <textarea>

<label for="message">Votre message</label>
<textarea id="message" name="message" rows="5"></textarea>

<textarea> se ferme, contrairement à <input>. Et attention : tout ce que vous écrivez entre les deux balises apparaît comme texte déjà saisi dans le champ. Pour un champ vide, collez les deux balises l'une contre l'autre.

Le bouton d'envoi — <button>

<button type="submit">Envoyer</button>

5 · Champs obligatoires — required

Ajoutez required à un champ, et le navigateur refuse l'envoi tant qu'il est vide — en affichant lui-même un message : 

<input type="email" id="courriel" name="courriel" required>

Comme controls sur la vidéo (projet 1), c'est un attribut booléen : il s'écrit seul, sans = ni valeur.

Cette vérification n'est pas une sécurité. Elle rend service à l'utilisateur honnête en lui signalant un oubli, mais elle se contourne en quelques secondes. Toute donnée reçue doit être revérifiée côté serveur — un sujet qui dépasse cette formation, mais qu'il faut savoir.

6 · Grouper des champs — <fieldset>

Pour réunir plusieurs champs liés sous un intitulé commun — typiquement un groupe de boutons radio : 

<fieldset>
  <legend>Niveau de difficulté souhaité</legend>

  <input type="radio" id="facile" name="difficulte" value="facile">
  <label for="facile">Facile</label>

  <input type="radio" id="difficile" name="difficulte" value="difficile">
  <label for="difficile">Difficile</label>
</fieldset>

Le point clé des boutons radio : ils partagent le même name — c'est ce qui les rend exclusifs, c'est-à-dire qu'en cocher un décoche l'autre. Mais chacun garde son id propre, puisque son label doit le viser individuellement.
