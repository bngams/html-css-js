Les deux points qui coincent

Les boutons radio : même name, id différents

C'est contre-intuitif et c'est le cœur de l'étape 4. Les deux boutons partagent name="formule" : c'est ce partage qui les rend exclusifs. Le navigateur comprend « ces deux boutons répondent à la même question », donc cocher l'un décoche l'autre.

Mais chacun garde son id propre, puisque son étiquette doit le viser individuellement. C'est la seule situation du cours où name et id ne se ressemblent pas.

Si vos deux boutons restent cochables ensemble, leurs name diffèrent. Si cliquer sur une étiquette ne coche rien, c'est le for qui ne correspond pas à l'id.

La zone de texte doit être vide

<textarea id="message" name="message" rows="5"></textarea>   ✅ vide

<textarea id="message" name="message" rows="5">
</textarea>                                                   ❌ contient un retour à la ligne

Contrairement à toutes les balises vues jusqu'ici, l'indentation compte ici : tout ce qui se trouve entre les deux balises est du texte pré-saisi.

Les erreurs fréquentes

Symptôme Cause probable
Cliquer sur une étiquette ne fait rien Le for du label et l'id du champ ne correspondent pas — souvent une coquille, une majuscule ou un accent
Les deux boutons radio peuvent être cochés en même temps Leurs name sont différents. Ils doivent partager le même
La zone de texte contient déjà du texte ou un espace Les balises <textarea> et </textarea> ne sont pas collées
Le bouton ne déclenche aucune vérification Il n'est pas type="submit", ou il est en dehors du <form>
La page se recharge et le formulaire se vide C'est normal. Sans action, le navigateur recharge la page. L'envoi réel se verra au jour 3
Le validateur signale « The for attribute of the label element must refer to a form control » Un for vise un id qui n'existe pas dans la page

Le réflexe qui attrape l'erreur n°1 : après chaque champ écrit, cliquez immédiatement sur son étiquette dans le navigateur. Deux secondes de vérification qui évitent de chercher la coquille parmi huit champs à la fin.
