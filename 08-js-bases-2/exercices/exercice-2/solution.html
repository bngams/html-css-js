Les quatre choses à retenir

1 · Le témoin qui arrête la boucle

trouve vaut false au départ, donc la condition trouve === false est vraie et la boucle tourne. Une seule ligne change tout : 

trouve = true;     ← au tour suivant, la condition est fausse

C'est la réponse à la question du cours — « qu'est-ce qui, dans le bloc, va rendre la condition fausse ? » Si vous ne pouvez pas désigner cette ligne du doigt, votre boucle est infinie.

2 · Tester l'annulation AVANT de convertir

L'ordre des six instructions n'est pas décoratif. Le test saisie === null doit précéder Number(saisie) : 

prompt annulé  →  null
Number(null)   →  0        ← l'abandon devient un nombre valide

Une fois converti, l'abandon est indiscernable d'une proposition de zéro. Le programme dirait « trop petit », redemanderait, le joueur annulerait à nouveau… sans issue. C'est la raison pour laquelle le test porte sur saisie, le texte brut.

Au projet 7, ce même Number(null) ne causait qu'une réponse bizarre. Dans une boucle, il enferme le joueur : le même défaut change de gravité selon le contexte.

3 · Pourquoi « Essais : 0 » à l'abandon immédiat

Vous jouezEssais comptésPourquoi
Annuler tout de suite0le break sort avant le essais++
Deux essais puis Annuler2deux tours complets ont eu lieu
abc puis le bon nombre2une saisie invalide reste un essai

Ces trois comportements découlent de la position du essais++ : après le test d'annulation, avant la conversion. Placé ailleurs, le décompte changerait.

4 · break, continue, et le pluriel

ÉcritureEffetRésultat
breakquitte la boucle0, 1, 2, 3
continuesaute au tour suivant0, 1, 3, 4

Et pour l'accord, l'écriture en une ligne vue au cours : 

essais + (essais > 1 ? " essais" : " essai")

C'est un if…else compacté : condition ? si vrai : si faux. Vous la croiserez souvent ; elle ne fait rien qu'un if ne saurait faire.

Les erreurs fréquentes

SymptômeCause
L'onglet se fige au chargement Le compteur de l'étape 1 ne diminue pas — la condition reste vraie pour toujours
La boîte revient sans fin quand j'annule Le test saisie === null manque, ou il est placé après la conversion
Le jeu s'arrête après une seule question trouve est passé à true hors du bon cas, ou la boucle est un if et non un while
Gagné en 1 essais ! L'accord du pluriel manque — voir le cours, §7
Le compte à rebours affiche 0 La condition est compte >= 0 au lieu de compte > 0
Valider à vide donne Trop petit. et compte un essai Ce n'est pas un défaut. Un champ vide rend "", qui n'est pas null — le test d'annulation ne s'applique pas — puis Number("") vaut 0
Décollage ! s'affiche trois fois La ligne est dans la boucle — elle doit être après l'accolade fermante
