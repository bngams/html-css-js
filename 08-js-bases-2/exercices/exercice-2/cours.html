La boucle for de l'exercice 1 savait d'avance combien de tours faire : autant qu'il y a de cases. Mais un joueur qui devine peut trouver au premier essai… ou au douzième.

2 · while — « tant que »

let i = 0;

while (i < 3) {
  console.log(i);
  i++;
}

Ça se lit : tant que i est plus petit que 3, répète le bloc. La condition est vérifiée avant chaque tour ; dès qu'elle devient fausse, la boucle s'arrête.

Un while est un for démonté. Les trois morceaux du for — départ, condition, pas — sont toujours là, mais séparés : le départ avant la boucle, le pas dedans. Rien de neuf, une autre disposition.

3 · ⚠️ Le danger réel : la boucle infinie

C'est le premier exercice où une erreur peut bloquer votre navigateur. Oubliez le i++ : 

let i = 0;

while (i < 3) {
  console.log(i);     ← i ne change JAMAIS
}

La condition reste vraie pour toujours. L'onglet se fige, ne répond plus, et vous devrez le fermer de force.

Si cela vous arrive : fermez l'onglet (Ctrl+W), corrigez le fichier, rouvrez la page. Vous ne cassez rien de définitif — mais c'est désagréable, alors prenez le réflexe.

La question à se poser avant d'écrire un while

« Qu'est-ce qui, dans le bloc, va finir par rendre la condition fausse ? » Si vous ne savez pas répondre, votre boucle est infinie.

4 · Sortir avec break

On peut aussi arrêter une boucle depuis l'intérieur, à tout moment : 

for (let x = 0; x < 5; x++) {
  if (x === 3) break;      ← on sort ici
  console.log(x);
}
// affiche 0, 1, 2
Mot-cléEffet
breakquitte la boucle entièrement
continuesaute au tour suivant
for (let x = 0; x < 5; x++) {
  if (x === 2) continue;   ← on saute juste ce tour
  console.log(x);
}
// affiche 0, 1, 3, 4

5 · Le jeu qui redemande

Voici enfin la boucle que le projet 7 vous devait : 

let trouve = false;

while (trouve === false) {
  const saisie = prompt("Votre proposition ?");
  const proposition = Number(saisie);

  if (proposition === secret) {
    trouve = true;         ← c'est CE changement qui arrête la boucle
  }
}

La variable trouve est le témoin : tant qu'elle vaut false, on redemande. C'est elle qui répond à la question « qu'est-ce qui va rendre la condition fausse ? ».

6 · ⚠️ Et si le joueur annule ?

Le piège le plus sérieux de cet exercice. Vous savez depuis le projet 7 qu'un prompt annulé rend null, et que Number(null) vaut 0.

Dans une boucle, cela devient grave : le joueur annule, le programme comprend « il propose 0 », ce n'est pas le secret, donc il redemande. Le joueur annule encore… et la boîte revient indéfiniment. Il ne peut plus sortir de la page.

La parade : tester l'annulation AVANT de convertir. 

const saisie = prompt("Votre proposition ?");

if (saisie === null) {
  break;                   ← le joueur abandonne, on sort
}

const proposition = Number(saisie);

Le test doit porter sur saisie, pas sur proposition : une fois convertie, l'annulation est devenue un 0 indiscernable.

7 · Compter les essais

let essais = 0;

while (trouve === false) {
  essais++;                ← un de plus à chaque tour
  …
}

alert("Trouvé en " + essais + " essais !");

Le détail qui fait la différence : « Trouvé en 1 essais » se remarque. Une condition règle le pluriel : 

essais + (essais > 1 ? " essais" : " essai")

Cette écriture avec ? et : est un if…else en une ligne. Retenez-la telle quelle pour aujourd'hui.

Et do…while ? Vous la croiserez — voici ce qu'elle change. Ce n'est pas au programme d'aujourd'hui : aucune étape ne la demande. Mais mieux vaut la reconnaître avant de la rencontrer.

La condition y est vérifiée après le tour, donc le bloc s'exécute toujours au moins une fois : 

let k = 99;

do {
  console.log("exécuté quand même");
} while (k < 3);
// s'affiche UNE fois, alors que 99 < 3 est faux

Utile quand on doit d'abord demander pour pouvoir tester. Retenez surtout while, qui couvre la plupart des besoins.
