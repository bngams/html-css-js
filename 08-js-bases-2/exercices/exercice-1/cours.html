Projet 8 · Exercice 1

Des listes et des boucles

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : ranger plusieurs valeurs dans une seule boîte — un tableau — et les parcourir sans écrire vingt fois la même ligne.

1 · Le problème : une boîte par valeur

Pour cinq fruits, il vous faudrait aujourd'hui cinq boîtes, et cinq console.log : 

const fruit1 = "Pomme";
const fruit2 = "Banane";
const fruit3 = "Cerise";
…

Avec cinquante fruits, la méthode s'effondre. Un tableau range toutes les valeurs dans une seule boîte.

2 · Créer un tableau

const fruits = ["Pomme", "Banane", "Cerise", "Mangue", "Poire"];
Le morceauSon rôle
[ ]les crochets : « ceci est un tableau »
les virgulesséparent les valeurs
fruitsle nom de la boîte — au pluriel, par habitude

3 · Lire une case : l'index

Les cases sont numérotées à partir de ZÉRO. C'est la source d'erreur numéro un avec les tableaux : 

fruits[0]    → "Pomme"      ← la PREMIÈRE case
fruits[1]    → "Banane"
fruits[2]    → "Cerise"
fruits[4]    → "Poire"      ← la DERNIÈRE
fruits[5]    → undefined    ⚠️ il n'y a pas de case 5

Demander une case qui n'existe pas ne provoque aucune erreur : on reçoit undefined, et le programme continue avec du vide.

4 · Compter : .length

fruits.length    → 5

.length donne le nombre de cases. Retenez la conséquence, qui revient sans cesse : 

Cinq fruits  →  length vaut 5
             →  les index vont de 0 à 4
             →  le DERNIER index est length - 1
fruits[fruits.length - 1]    → "Poire"

5 · Répéter : la boucle for

Une boucle exécute le même bloc plusieurs fois, en faisant varier un compteur : 

for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);
}
Le morceauSon rôle
let i = 0départ : le compteur commence à 0
i < fruits.lengthcondition : on continue tant qu'elle est vraie
i++pas : ajoute 1 au compteur à chaque tour
{ … }ce qu'on répète

i++ est un raccourci pour i = i + 1 — l'écriture que vous connaissez depuis le projet 6. Les deux sont identiques ; i++ est simplement l'habitude du métier dans une boucle.

Le piège du <=

Écrire i <= fruits.length fait un tour de trop : 

i < 5     → i vaut 0,1,2,3,4        ✅ cinq tours
i <= 5    → i vaut 0,1,2,3,4,5      ⚠️ six tours

Au dernier tour, fruits[5] vaut undefined — et aucune erreur ne vous prévient. Vous verrez simplement un undefined apparaître en fin de liste.

La règle : i < length, avec un chevron simple.

6 · Plus simple : for…of

Quand le compteur ne vous sert qu'à lire chaque case, for…of fait le travail sans compteur du tout : 

for (const fruit of fruits) {
  console.log(fruit);
}

À chaque tour, fruit contient la valeur de la case suivante. Plus d'index, donc plus de piège <=.

SituationUtilisez
Vous avez besoin du numéro de la case for (let i = …)
Vous voulez seulement chaque valeur for…of

Il existe aussi for…in — n'en faites pas usage sur un tableau. Il donne les index, et sous forme de texte : "0", "1"… ce qui rouvre tous les pièges de conversion du projet 7. Il sert aux objets, vus à l'exercice 3.

7 · Ajouter, assembler, trier

InstructionEffet
fruits.push("Kiwi") ajoute une case à la fin
fruits.join(" - ") assemble tout en un seul texte

Ce sont les deux que vous utiliserez dans cet exercice.

Et pour trier ? Vous croiserez sort() — voici son piège. Ce n'est pas au programme d'aujourd'hui, mais mieux vaut le savoir avant de le rencontrer. 

[10, 9, 2].sort()    → [10, 2, 9]     ⚠️ pas ce qu'on attend

sort() compare les valeurs en tant que texte : c'est le piège de "10" < "9" du projet 7, sous une autre forme. Pour trier de vrais nombres, on lui donne une règle — [10, 9, 2].sort((a, b) => a - b) rend bien [2, 9, 10].

Second piège, plus discret : sort() modifie le tableau lui-même, il n'en rend pas une copie triée. Après fruits.sort(), l'ordre d'origine est perdu.

8 · push modifie, même avec const

const fruits = ["Pomme"];
fruits.push("Kiwi");        ✅ autorisé
fruits = ["Autre chose"];   ✋ TypeError

const interdit de remplacer la boîte, pas d'en modifier le contenu. On peut donc ajouter des cases à un tableau déclaré en const — c'est même l'usage normal.
