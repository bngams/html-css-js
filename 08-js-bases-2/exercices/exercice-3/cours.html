Projet 8 · Exercice 3

Décrire une chose : les objets

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : ranger sous un seul nom les caractéristiques d'une chose — et lire la notation JSON, celle de toutes les données du web.

1 · Le tableau ne suffit plus

Un tableau range des valeurs de même nature, repérées par un numéro. Mais pour décrire un livre, le numéro ne veut rien dire : 

const livre = ["La Horde", "Damasio", 712];

livre[1]     → "Damasio"    ← le 1, c'était l'auteur ? le titre ?

Un objet remplace les numéros par des noms : 

const livre = {
  titre: "La Horde du Contrevent",
  auteur: "Damasio",
  pages: 712
};
Le morceauSon rôle
{ }les accolades : « ceci est un objet »
titreune clé — le nom de la case
:sépare la clé de sa valeur
"Damasio"la valeur
les virgulesséparent les paires — pas après la dernière

Tableau ou objet ? Plusieurs choses du même genre → tableau. Plusieurs aspects d'une seule chose → objet. Une médiathèque a un tableau de livres ; chaque livre est un objet.

2 · Lire une propriété

livre.titre         → "La Horde du Contrevent"
livre["auteur"]     → "Damasio"

Les deux écritures font la même chose. Le point est plus court et se lit mieux ; les crochets servent quand le nom de la clé est dans une variable — vous en aurez besoin à l'étape du parcours.

Une propriété qui n'existe pas rend undefined, sans la moindre erreur : 

livre.editeur       → undefined

C'est le même comportement que fruits[5] à l'exercice 1 : JavaScript répond « rien » et continue. Une faute de frappe sur un nom de clé ne se signale donc jamais toute seule.

3 · Modifier, ajouter, retirer

livre.pages = 712;          ← modifie
livre.editeur = "La Volte"; ← AJOUTE une clé qui n'existait pas
delete livre.pages;         ← retire la clé

Comme pour les tableaux, const n'empêche rien de cela. Il interdit de remplacer l'objet entier (livre = { … }), pas d'en changer le contenu. C'est pourquoi on déclare presque toujours un objet avec const.

Note : delete n'est demandé par aucune étape aujourd'hui — il figure ici pour que vous le reconnaissiez le jour où vous le croiserez.

4 · Parcourir un objet : for…in

À l'exercice 1, for…in était déconseillé sur un tableau. Voici enfin son usage légitime : 

for (const cle in livre) {
  console.log(cle, "=", livre[cle]);
}

À chaque tour, cle contient le nom de la propriété. Pour obtenir la valeur, on écrit livre[cle] — avec des crochets, puisque le nom est dans une variable.

livre.cle ne fonctionnerait pas : JavaScript chercherait une propriété littéralement appelée cle, et rendrait undefined. C'est l'erreur la plus fréquente sur ce point.

Et pour obtenir seulement les noms, ou seulement les valeurs ? Ce n'est pas au programme d'aujourd'hui — aucune étape ne le demande — mais vous les croiserez : 

Object.keys(livre)     → ["titre", "auteur", "pages"]
Object.values(livre)   → ["La Horde du Contrevent", "Damasio", 712]

Deux tableaux — vous savez déjà les parcourir avec for…of. Retenez surtout for…in, qui donne les deux à la fois.

5 · Des objets dans des objets

const media = {
  nom: "Trois Rivières",
  adresse: { ville: "Toulouse", cp: "31000" }
};

media.adresse.ville     → "Toulouse"

⚠️ Le piège à deux étages. Une clé absente rend undefined, sans erreur — vous le savez. Mais aller chercher dans ce undefined fait tout arrêter : 

media.horaires          → undefined       (pas d'erreur)
media.horaires.lundi    → TypeError: Cannot read properties of undefined

C'est exactement le mécanisme du projet 7, quand querySelector ne trouvait rien : chercher est permis, entrer dedans ne l'est pas. Quand vous voyez ce message, remontez d'un cran : c'est le niveau au-dessus qui est absent.

6 · Un tableau d'objets

C'est la structure la plus courante du web — et celle de votre dernier projet : 

const catalogue = [
  { titre: "Dune", pages: 900 },
  { titre: "La Horde", pages: 712 },
  { titre: "Fondation", pages: 420 }
];

catalogue.length        → 3
catalogue[0].titre      → "Dune"

Et l'on combine ce qu'on sait déjà :

for (const livre of catalogue) {
  console.log(livre.titre);
}

Rien de neuf ici : un for…of de l'exercice 1, et un accès par point de la section 2. C'est l'assemblage qui est puissant — et c'est sous cette forme que les données arrivent d'un serveur.

Additionner au fil de la boucle : l'accumulateur

Pour faire une somme, on part d'une boîte à 0 et on y ajoute à chaque tour. Ce motif porte un nom — un accumulateur — et vous le réutiliserez souvent : 

let total = 0;

for (const livre of catalogue) {
  total = total + livre.pages;
}

Le .pages n'est pas optionnel. Ajouter livre tout entier ne provoque aucune erreur : le + se met à coller du texte, et le total devient 0[object Object][object Object]… — le piège du projet 6, sous une forme nouvelle.

7 · JSON — le même objet, en texte

Pour transmettre un objet, il faut le transformer en texte. C'est le rôle de JSON — JavaScript Object Notation : 

JSON.stringify(livre)
→ {"titre":"Dune","auteur":"Herbert","pages":900}
InstructionTransformeRésultat
JSON.stringify(obj) objet → texte une chaîne
JSON.parse(txt) texte → objet un objet

Le résultat de stringify est du TEXTE. Il ressemble à l'objet, mais typeof répond "string" — et l'on ne peut plus écrire .titre dessus. C'est la même distinction que "25" et 25 au projet 6 : l'apparence n'est pas le type.

Deux différences avec l'écriture JavaScript

Objet JavaScriptJSON
Les clés titre: … "titre": … — toujours entre guillemets doubles
Les fonctions autorisées perdues sans prévenir

Un texte JSON mal formé — guillemets simples, virgule en trop — fait échouer JSON.parse avec une SyntaxError. Contrairement aux pièges silencieux de ce cours, celui-là se voit : c'est une bonne nouvelle.
