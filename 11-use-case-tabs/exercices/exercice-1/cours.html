Projet 11 · Cas pratique

Le système d'onglets

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez faire ici : écrire votre premier composant — un morceau d'interface qui fonctionne tout seul.

Une seule notion nouvelle : lire un attribut data-. Tout le reste vient des projets 9 et 10.

1 · Ce qu'est un système d'onglets

Plusieurs vues occupent le même espace. Une seule est visible à la fois, et une barre de boutons permet de choisir laquelle. 

┌──────────┬──────────┬──────────┐
│Catalogue │ Emprunts │ Retards  │   ← les onglets
└══════════┴──────────┴──────────┘
│                                │
│   le panneau de l'onglet actif │   ← un seul visible
│                                │
└────────────────────────────────┘

Le mot-clé, c'est l'exclusivité. À tout instant : un seul panneau visible, un seul onglet souligné. Tout le code découle de cette règle.

2 · Le HTML dit déjà qui va avec qui

Chaque bouton porte un attribut qui désigne son panneau : 

<button class="tab" data-content-id="content2">Emprunts</button>

<div id="content2" class="tab-content"> … </div>
          ↑ le même texte des deux côtés

Un attribut qui commence par data- est un attribut libre. Le navigateur ne lui donne aucun sens : il est là pour vous, pour transporter une information de votre HTML vers votre JavaScript.

On aurait pu deviner le lien par la position (1er bouton → 1er panneau). Mais le jour où l'ordre change dans le HTML, tout casse en silence. L'attribut, lui, dit les choses explicitement.

3 · Le CSS est déjà écrit — et c'est lui qui décide

Deux classes existent dans la page de travail. Votre code n'a qu'à les poser :

ClasseSur quoiCe que le CSS en fait
tab-activeun bouton fond blanc, texte bleu, soulignement
activeun panneau display: block — il devient visible 
.tab-content          { display: none; }    ← caché par défaut
.tab-content.active   { display: block; }   ← visible si la classe est là

N'écrivez jamais .style.display dans ce projet. C'est la règle du projet 9, exercice 2 — et voici pourquoi, concrètement. 

panneau.classList.add("active")   → <div class="tab-content active">
panneau.style.display = "block"   → <div class="tab-content" style="display: block;">

Les deux affichent le panneau. Mais le second écrit dans la page une décision d'apparence qui appartenait au CSS.

4 · getAttribute — lire l'attribut

const identifiant = onglet.getAttribute("data-content-id");
→ "content2"                                    ← du TEXTE

const panneau = document.querySelector("#" + identifiant);
→ l'élément <div id="content2">

Deux gestes enchaînés : on lit un texte dans le bouton, puis on s'en sert pour fabriquer un sélecteur. Le "#" est celui du projet 9, exercice 1 — un identifiant se cherche avec un dièse.

5 · Éteindre tout, rallumer un

C'est l'algorithme complet, et il tient en trois temps : 

1. retirer "tab-active" de TOUS les onglets
2. retirer "active"     de TOUS les panneaux
3. poser les deux classes sur le SEUL couple choisi

Pourquoi tout éteindre d'abord ? Parce qu'on ne sait pas ce qui était allumé avant. Éteindre uniquement « le précédent » demanderait de s'en souvenir — une deuxième vérité à maintenir, qui finira par diverger de la page.

Tout éteindre coûte trois tours de boucle et ne peut pas se tromper.

6 · Un écouteur par onglet

for (const onglet of onglets) {
  onglet.addEventListener("click", function () {
    activer(onglet);
  });
}

La boucle du projet 9 et l'écouteur du projet 10, assemblés. Chaque bouton reçoit sa propre écoute, et chacune sait quel onglet elle concerne.

On appelle activer(onglet), pas activer. Ce n'est pas une contradiction avec le projet 10 : ici la fonction anonyme est la fonction confiée, et elle appelle activer avec le bon argument, au moment du clic.

7 · L'état de départ

Au chargement, tous les panneaux sont cachés par le CSS : la zone de contenu est vide. Un composant qui s'ouvre sur du vide est un composant cassé. 

activer(onglets[0]);   ← la dernière ligne du fichier

La même fonction sert au clic et au démarrage. C'est le geste du projet 10, exercice 2 : une fonction, deux appelants. Rien à dupliquer.

onglets[0] — le premier de la collection, par son index. Une NodeList s'indexe comme un tableau (projet 9, exercice 1).

8 · ⚠️ Deux pièges de ce composant

Oublier d'éteindre les onglets. Si vous ne retirez que la classe des panneaux, l'affichage sera correct mais plusieurs onglets resteront soulignés — le composant ment sur son propre état.

Chercher le panneau sans le dièse. querySelector("content2") cherche une balise nommée « content2 », qui n'existe pas : vous obtenez null.

Ce qui suit dépend de votre code : si vous avez écrit un if (panneau), rien ne s'affiche en silence ; sinon vous verrez TypeError: Cannot read properties of null (reading 'classList').
