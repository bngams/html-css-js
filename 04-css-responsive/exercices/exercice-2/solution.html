Le code complet

/* ── PARTIE 2 : le style de base (petits écrans) ── */

.banniere {
  background-color: #14457b;
  padding: 1rem;
  text-align: center;
}

.logo {
  color: #fff;
  font-weight: bold;
  font-size: 1.3rem;
  margin: 0;
}

.menu {
  display: flex;
  flex-wrap: wrap;
  justify-content: center;
  gap: 1rem;
}

.menu a {
  color: #fff;
  text-decoration: none;
}

h1 {
  font-size: 1.6rem;
}


/* ── PARTIE 3 : les enrichissements ── */

@media (min-width: 700px) {

  .banniere {
    display: flex;
    justify-content: space-between;
    align-items: center;
    padding: 1rem 2rem;
    text-align: left;
  }

  .grille {
    display: flex;
    gap: 1rem;
  }

  .espace {
    margin-bottom: 0;
  }

}

@media (min-width: 1000px) {

  h1 {
    font-size: 2.4rem;
  }

}

Le fichier commenté est dans solution/style.css — et la page est visible ici. Redimensionnez-la pour voir les deux basculements.

Les trois états de la page

Largeur Media queries actives Résultat
Moins de 700 px aucune Tout empilé : logo au-dessus du menu, espaces les uns sous les autres
700 à 999 px celle de 700 px Bannière étalée, trois espaces côte à côte
1000 px et plus les deux Idem, plus le titre agrandi

Notez la troisième ligne : à 1200 px, les deux media queries s'appliquent en même temps. Elles ne s'excluent pas — elles s'empilent. C'est pourquoi leur ordre d'écriture décide du résultat.

Les trois points qui comptent

1 · La règle de base est celle du petit écran

Regardez l'étape 1 : la bannière n'a pas de display: flex. C'est délibéré — sur un téléphone, le logo et le menu doivent rester l'un sous l'autre, ce qui est déjà le comportement par défaut.

Voilà l'esprit du mobile-first : le cas le plus contraint demande le moins de code. On n'écrit que pour enrichir, jamais pour défaire.

2 · Une media query n'annule rien

Le fond bleu de la bannière n'est écrit qu'une fois, dans la partie 2. Il n'est pas répété dans la media query, et pourtant il reste bleu à 1200 px.

Une media query ajoute des règles quand sa condition est remplie. Tout ce qui est défini en dehors continue de s'appliquer. N'y écrivez donc que les différences — c'est ce qui rend le fichier lisible.

3 · flex-wrap sur le menu n'est pas décoratif

Quatre liens ne tiennent pas sur une ligne de 360 px. Sans flex-wrap: wrap, Flexbox les comprimerait jusqu'à les rendre illisibles plutôt que de passer à la ligne — il refuse de le faire par défaut.

Les erreurs fréquentes

Symptôme Cause probable
Tout est inversé : étalé sur téléphone, empilé sur ordinateur max-width a été écrit au lieu de min-width
Le titre reste petit sur grand écran La media query de 1000 px est écrite avant celle de 700 px : à spécificité égale, la dernière gagne
Plus rien ne fonctionne à partir d'un certain point du fichier Une accolade fermante manque — une media query en demande deux. Le validateur CSS le signale
Les liens du menu sont écrasés sur téléphone flex-wrap: wrap manque sur .menu
La bannière reste centrée sur grand écran text-align: left manque dans la media query : le center de la partie 2 reste actif
Les espaces gardent un écart vertical entre eux margin-bottom: 0 manque sur .espace dans la media query

Le réflexe qui diagnostique une media query : ouvrez l'inspecteur et sélectionnez l'élément concerné. Le panneau des styles affiche les règles groupées par media query, avec la condition en en-tête. Si votre bloc n'y figure pas à la largeur testée, sa condition n'est pas remplie — vérifiez le sens de min- / max-.
