Les media queries

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : appliquer des règles différentes selon la largeur de l'écran — et surtout, dans quel ordre les écrire pour ne pas s'y perdre.

1 · Ce que les fondations ne suffisent pas à faire

L'exercice 1 l'a montré : avec max-width, des unités relatives et img { max-width: 100% }, une page rétrécit déjà proprement.

Mais certaines choses ne peuvent pas se contenter de rétrécir :

  • un menu horizontal de six liens, qui devient illisible sous 400 px ;
  • une grille de trois colonnes, qui doit passer à une seule ;
  • un titre de 3 rem, écrasant sur un petit écran ;
  • un encadré latéral, qui doit passer sous le contenu.

Ces cas demandent de réorganiser, pas seulement de redimensionner. C'est le travail des media queries.

2 · La syntaxe

Une media query est un bloc qui contient des règles :

@media (min-width: 700px) {

  .grille {
    display: flex;
    gap: 1rem;
  }

}

À lire ainsi : « à partir de 700 px de large, applique ces règles ». En dessous, le bloc est ignoré comme s'il n'existait pas.

Deux accolades, pas une. Une media query enveloppe des règles qui ont déjà leurs propres accolades. L'oubli de la dernière est l'erreur la plus fréquente — et elle casse silencieusement tout ce qui suit dans le fichier.

3 · min-width ou max-width ?

Écriture S'applique Sens
(min-width: 700px) à partir de 700 px « au moins 700 px » — les grands écrans
(max-width: 699px) jusqu'à 699 px « au plus 699 px » — les petits écrans

Le moyen de ne plus se tromper : lisez min-width comme « la fenêtre fait au minimum… ». Une largeur minimale de 700 px désigne donc tout ce qui est plus grand. Beaucoup de débutants comprennent l'inverse.

4 · L'approche mobile-first

Deux façons d'écrire la même page. Elles produisent le même résultat, mais l'une se maintient et l'autre non.

❌ Desktop-first — l'ordre spontané

.grille {
  display: flex;          /* pensé pour l'ordinateur */
  gap: 2rem;
}

@media (max-width: 699px) {
  .grille {
    display: block;       /* on DÉFAIT pour le téléphone */
    gap: 0;
  }
}

On écrit d'abord la version riche, puis on la démonte pour les petits écrans. Chaque ajout futur devra être démonté à son tour.

✅ Mobile-first — l'ordre recommandé

.grille {
  /* rien : l'empilement est le comportement par défaut */
}

@media (min-width: 700px) {
  .grille {
    display: flex;        /* on ENRICHIT pour l'ordinateur */
    gap: 2rem;
  }
}

On part du plus simple — un écran étroit, tout empilé — et on ajoute à mesure que la place le permet.

Trois raisons de préférer mobile-first :

  • On écrit moins. L'empilement vertical est déjà le comportement par défaut du navigateur : il n'y a rien à écrire pour l'obtenir.
  • Le cas de base est le plus contraint. Concevoir d'abord pour 360 px force à hiérarchiser ; l'inverse conduit à entasser puis à élaguer.
  • C'est la convention du métier. Vous lirez du code écrit ainsi, et vos collègues l'attendront.

5 · Où placer le point de rupture

Ne visez pas des appareils. « 375 px pour l'iPhone, 768 px pour l'iPad » était la méthode de 2012 : il existe aujourd'hui des centaines de tailles, et elles changent chaque année.

La bonne méthode : élargissez votre fenêtre jusqu'à ce que la mise en page devienne laide, et placez le point de rupture là. C'est le contenu qui décide, pas le catalogue d'un fabricant.

Deux ou trois points de rupture suffisent presque toujours :

Valeur courante Ce qu'elle sépare
600px – 700px Téléphone ↔ tablette
900px – 1000px Tablette ↔ ordinateur

6 · L'ordre compte

Les media queries n'ont aucune priorité particulière : elles obéissent à la cascade, comme toute règle CSS (projet 3, exercice 1). En mobile-first, on les écrit donc de la plus petite à la plus grande, à la fin du fichier : 

/* 1. les règles de base, pour tous les écrans */
.carte { … }

/* 2. puis les enrichissements, par largeur croissante */
@media (min-width: 700px)  { … }
@media (min-width: 1000px) { … }

Dans l'ordre inverse, la plus petite écraserait la plus grande sur les écrans concernés par les deux — puisqu'à spécificité égale, c'est la dernière écrite qui gagne. Votre règle « grand écran » serait annulée sans que rien ne le signale.

7 · Ce qu'on met dans une media query

Le moins possible. Une media query ne devrait contenir que ce qui change vraiment : 

/* ✅ seulement ce qui diffère */
@media (min-width: 700px) {
  .grille { display: flex; }
}

/* ❌ tout réécrire */
@media (min-width: 700px) {
  .grille {
    display: flex;
    background: #fff;      /* déjà défini plus haut */
    padding: 1rem;         /* déjà défini plus haut */
    border-radius: 8px;    /* déjà défini plus haut */
  }
}

Les propriétés déjà définies hors de la media query restent actives : elles ne sont pas « annulées » par le changement de largeur. N'y répétez que les différences.
