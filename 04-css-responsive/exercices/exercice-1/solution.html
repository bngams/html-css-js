Le point central : width contre max-width

Les trois règles fautives avaient toutes le même défaut, et la correction est toujours la même :

Écriture Ce que le navigateur comprend
width: 900px « Fais exactement 900 px » — même sur un écran de 360 px, d'où le débordement
max-width: 900px « Ne dépasse pas 900 px, mais rétrécis autant qu'il faut »

La règle pratique : en responsive, width avec une valeur fixe est presque toujours une erreur. Réservez-le aux éléments dont la taille ne doit vraiment jamais changer — une icône, par exemple.

Trois points que la solution pousse plus loin

1 · Pourquoi aucune media query n'a été nécessaire

C'est le message de cet exercice : une page correctement construite s'adapte déjà, sans point de rupture. Les media queries de l'exercice 2 ne serviront qu'à réorganiser ce qui ne peut pas se contenter de rétrécir — un menu horizontal, une grille de colonnes.

L'erreur classique du débutant consiste à faire l'inverse : garder des largeurs fixes, puis empiler des media queries pour rattraper les dégâts à chaque taille d'écran. On se retrouve avec dix points de rupture et une page qui casse dès qu'un téléphone a une largeur inhabituelle.

2 · line-height s'écrit sans unité

line-height: 1.6;      ✅ 1,6 fois la taille du texte
line-height: 1.6rem;   ⚠️ valeur figée

Sans unité, la valeur est un multiplicateur : chaque texte calcule son interlignage d'après sa propre taille. Avec une unité, un titre de 2rem hériterait d'un interlignage prévu pour du texte courant, et ses lignes se chevaucheraient.

3 · Les attributs width et height de l'image

Vous avez peut-être remarqué width="1200" height="600" sur la balise <img>. Ils ne fixent pas la taille d'affichage — le CSS l'emporte.

Leur rôle : indiquer les proportions au navigateur avant que l'image ne soit chargée, pour qu'il réserve la place. Sans eux, la page sursaute au moment où l'image arrive. C'est une bonne pratique à conserver.

Les erreurs fréquentes

Symptôme Cause probable
La barre de défilement horizontale persiste Une largeur fixe subsiste quelque part. Cherchez width: suivi d'une valeur en pixels
L'image déborde toujours La règle img manque, ou vise une classe qui n'existe pas — elle doit viser la balise
L'image est écrasée, déformée height: auto manque : la hauteur d'origine est conservée pendant que la largeur rétrécit
Les blocs restent étroits sur grand écran max-width a été remplacé par width: 100% sans limite haute — le texte devient alors trop long à lire
Rien ne bouge quand je redimensionne Vous rechargez style.css au lieu de travail.html, ou le fichier n'est pas enregistré

Le réflexe qui trouve le coupable : à la largeur où la barre horizontale apparaît, ouvrez l'inspecteur et survolez les éléments un à un dans le panneau HTML. Celui qui dépasse du cadre de l'écran se surligne au-delà du bord — vous le repérez en quelques secondes.
