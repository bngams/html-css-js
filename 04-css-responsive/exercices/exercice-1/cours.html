Projet 4 · Exercice 1

Le viewport et les unités

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : les trois fondations du responsive — la balise qui dit au téléphone de ne pas tricher, les unités qui s'adaptent, et la règle qui empêche les images de déborder.

Aucune media query dans ce chapitre. Vous verrez qu'on peut déjà aller très loin sans elles.

1 · Pourquoi une page « normale » est illisible sur téléphone

Prenez une page conçue pour un écran d'ordinateur et ouvrez-la sur un téléphone. Deux choses se produisent :

  • le texte devient minuscule, illisible sans zoomer ;
  • une barre de défilement horizontale apparaît.

La cause remonte aux débuts du web mobile. À l'époque, aucun site n'était prévu pour les petits écrans. Les téléphones ont donc adopté une ruse : faire semblant d'avoir un écran large — environ 980 pixels — puis dézoomer l'ensemble pour le faire tenir.

Résultat : la page s'affiche en entier, mais en tout petit. C'était un moindre mal en 2007. Aujourd'hui, c'est un défaut.

2 · La balise qui corrige tout — meta viewport

Une seule ligne, dans le <head>, demande au téléphone de cesser de tricher : 

<meta name="viewport" content="width=device-width, initial-scale=1.0">
Morceau Ce qu'il demande
width=device-width « Utilise la vraie largeur de l'écran, pas 980 px »
initial-scale=1.0 « N'applique aucun zoom au chargement »

Vous l'écrivez depuis le projet 1 sans qu'on vous ait dit à quoi elle servait : elle est dans toutes les pages de cette formation. La voici expliquée.

C'est le prérequis absolu du responsive. Sans elle, toutes les media queries du monde resteront sans effet sur un vrai téléphone — le navigateur croira avoir 980 px de large.

Un piège du développement sur ordinateur : réduire la fenêtre de votre navigateur fonctionne même sans cette balise. Le défaut ne se voit que sur un vrai téléphone, ou dans le mode appareil mobile de l'inspecteur. C'est pourquoi l'oubli passe si souvent inaperçu.

3 · Les unités fixes contre les unités relatives

Deuxième fondation : cesser de tout mesurer en pixels. 

.carte {
  width: 600px;     /* FIXE — 600px, même sur un écran de 360px */
}

Sur un téléphone de 360 px, cette carte déborde de 240 px. D'où la barre de défilement horizontale — le symptôme le plus courant d'une page mal adaptée.

Les unités qui s'adaptent

Unité Relative à Usage
% La largeur de l'élément parent Largeurs de blocs
rem La taille de police de base du navigateur (16 px par défaut) Tailles de texte et espacements
vw 1 % de la largeur de la fenêtre Grands titres, à manier avec prudence

Pourquoi rem plutôt que px pour le texte : une personne malvoyante peut augmenter la taille de police par défaut de son navigateur. Les valeurs en rem suivent ce réglage ; celles en px l'ignorent purement et simplement.

La conversion est simple : 1rem = 16 px, donc 1.5rem = 24 px, et 0.875rem = 14 px.

4 · max-width, l'outil le plus utile du responsive

Comparez ces deux règles :

Règle Comportement
width: 800px Toujours 800 px — déborde sur un petit écran
max-width: 800px Jusqu'à 800 px, puis rétrécit librement

Vous l'utilisez déjà depuis le projet 3, pour centrer le conteneur. Sa vraie raison d'être, la voici : c'est ce qui rend un bloc adaptable sans une seule media query.

5 · Les images, coupables n°1 du débordement

Une image s'affiche par défaut à sa taille réelle. Une photo de 1200 px de large dans une page ouverte sur un téléphone de 360 px déborde de 840 px — et emporte toute la mise en page avec elle.

La règle qui règle définitivement le problème :

img {
  max-width: 100%;
  height: auto;
}
Déclaration Rôle
max-width: 100% L'image ne dépassera jamais la largeur de son conteneur
height: auto La hauteur suit, pour conserver les proportions

Sans height: auto, une image réduite en largeur garderait sa hauteur d'origine et se retrouverait écrasée. Les deux vont toujours ensemble.

Cette règle figure dans presque toutes les feuilles de style professionnelles, posée une fois pour toutes sur img.

6 · Ce qu'on obtient sans media query

Avec seulement ces trois fondations, une page devient déjà adaptable :

* { box-sizing: border-box; }

img {
  max-width: 100%;
  height: auto;
}

.conteneur {
  max-width: 900px;
  margin: 0 auto;
  padding: 1rem;
}

Cette page rétrécit proprement jusqu'au téléphone. Les media queries du chapitre suivant ne serviront qu'à réorganiser ce qui ne peut pas se contenter de rétrécir — un menu horizontal, une grille de colonnes.

C'est l'ordre de travail à retenir : d'abord les fondations (viewport, unités relatives, max-width), et seulement ensuite les media queries pour les cas récalcitrants. Beaucoup de débutants font l'inverse et empilent les points de rupture pour compenser des largeurs fixes.
