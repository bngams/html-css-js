const age = 20;

if (age >= 18) {
  console.log("Majeur");
} else {
  console.log("Mineur");
}

const saisie = "20";

console.log("saisie === 20 :", saisie === 20);
console.log("saisie == 20 :", saisie == 20);

const saisieNombre = Number(saisie);

console.log("saisieNombre === 20 :", saisieNombre === 20);

  tarif = 24;

Les quatre choses à retenir

1 · Un seul bloc s'exécute

Vous avez écrit six console.log, la console en affiche cinq. Celui du bloc else n'a jamais tourné, parce que age vaut 20.

Ce n'est pas un oubli, c'est la définition d'une condition : elle ouvre deux chemins, et le programme n'en emprunte qu'un. Changez age en 15 et c'est l'autre ligne qui apparaît.

2 · === compare la valeur et le type

ComparaisonRésultatPourquoi
"20" === 20 false texte ≠ nombre — les types diffèrent
"20" == 20 true le texte est converti d'abord, puis comparé
Number("20") === 20 true deux vrais nombres, sans conversion cachée

Pourquoi préférer celui qui dit false ? Parce qu'il dit la vérité. == a l'air plus pratique, mais il masque le problème au lieu de le résoudre — et ses règles de conversion réservent des surprises que personne ne retient.

La règle professionnelle : === toujours. Si les types ne correspondent pas, on convertit explicitement, avec Number().

3 · Le lien avec prompt()

Cet exercice utilise "20" écrit à la main, mais c'est exactement ce que vous recevrez d'un prompt() — vu au projet 6, et que vous réutiliserez dès l'exercice 3 de ce projet : 

let saisie = prompt("Votre âge ?");   // "20", du TEXTE

if (saisie === 20) { … }              ⚠️ ne se déclenche JAMAIS
if (Number(saisie) === 20) { … }      ✅

Une condition qui ne se déclenche jamais, sans aucune erreur rouge, vient presque toujours d'un type non converti. C'est le premier réflexe de diagnostic à prendre.

4 · Un seul = dans un if ne compare rien

À l'étape 8, remplacer === par = produit : 

TypeError: Assignment to constant variable.

Ici l'erreur vous sauve — parce que saisieNombre est un const. Mais elle n'apparaît pas toujours. Avec une boîte déclarée en let : 

let n = 20;
if (n = 18) { console.log("bloc exécuté"); }
// → le bloc s'exécute, n vaut maintenant 18, AUCUNE erreur

Le = a rangé 18 dans n, et la condition s'est déclenchée parce que 18 est une valeur « vraie ». Rien ne vous prévient. C'est la meilleure raison d'écrire === par réflexe.
