Projet 7 · Exercice 1

Si… sinon

  • 📖 Cours

Ce que vous allez apprendre ici : faire prendre une décision à votre code — et éviter le piège de comparaison qui rend une condition fausse pour toujours.

1 · Jusqu'ici, tout s'exécutait pareil

Au projet 6, vos instructions se déroulaient de haut en bas, dans le même ordre, à chaque fois. Une condition permet d'exécuter un bloc seulement si quelque chose est vrai. 

if (age >= 18) {
  console.log("Majeur");
}
Le morceauSon rôle
if« si »
(age >= 18)la question, entre parenthèses
{ … }ce qu'on fait si c'est vrai

Pas de point-virgule après l'accolade fermante. On écrit } et on passe à la ligne. Le point-virgule termine une instruction ; un bloc n'en est pas une.

2 · else — et sinon ?

if (age >= 18) {
  console.log("Majeur");
} else {
  console.log("Mineur");
}

else se traduit par « sinon ». Un seul des deux blocs s'exécute, jamais les deux.

3 · Poser la question : les comparaisons

Entre les parenthèses, on écrit une comparaison. Elle produit true ou false — le type booléen vu au projet 6.

OpérateurQuestion poséeExemple vrai
>plus grand que5 > 3
<plus petit que3 < 5
>=plus grand ou égal5 >= 5
<=plus petit ou égal3 <= 5
===égal5 === 5
!==différent5 !== 3

Trois signes égal pour comparer, un seul pour ranger. C'est la confusion la plus fréquente du débutant : 

age = 18     ← RANGE 18 dans age (projet 6)
age === 18   ← DEMANDE si age vaut 18

Écrire if (age = 18) ne pose aucune question : cela modifie age, puis la condition prend la valeur de ce qu'on vient de ranger — ici 18, que JavaScript considère comme vraie. Le bloc s'exécute donc, mais pas parce qu'on a comparé quoi que ce soit. Aucune erreur rouge ne vous prévient.

Une valeur seule peut aussi être jugée vraie ou fausse. Hors de toute comparaison, JavaScript considère comme fausses la valeur 0 et le texte vide "" — et comme vraies presque toutes les autres, y compris le texte "0".

C'est ce qui explique le comportement ci-dessus, et vous le vérifierez au bonus de l'exercice.

4 · Le piège central : == contre ===

Il existe aussi == à deux signes. La différence est mince à lire, énorme à l'usage :

OpérateurCe qu'il fait
=== (strict) compare la valeur et le type
== (lâche) convertit d'abord, puis compare — il ferme les yeux sur le type 
"5" === 5     → false     texte ≠ nombre
"5"  ==  5    → true      le texte a été converti

La règle à retenir : utilisez toujours ===. Comparer sans regarder le type produit des surprises difficiles à traquer. Les professionnels écrivent === par défaut, et !== pour « différent ».

5 · Pourquoi cela vous concerne maintenant

Vous savez depuis le projet 6 que prompt() renvoie toujours du texte. Une condition sur une saisie tombe donc droit dans le piège : 

let saisie = prompt("Votre âge ?");   // "25", du TEXTE

saisie === 25          → false    ⚠️ JAMAIS vrai
Number(saisie) === 25  → true     ✅

Convertissez d'abord, comparez ensuite. Une condition qui ne se déclenche jamais, sans erreur rouge, vient presque toujours de là.

6 · Comparer du texte : attention à l'ordre

On peut comparer deux textes, mais le classement se fait caractère par caractère, comme dans un dictionnaire — pas par la valeur numérique : 

"abc" < "abd"   → true    ordre alphabétique
"10"  < "9"     → true    ⚠️ "1" vient avant "9"
 10   <  9      → false   ✅ vrais nombres

"10" < "9" est vrai, et c'est logique pour un dictionnaire : « 1 » vient avant « 9 », on ne va pas plus loin. Encore une raison de convertir avant de comparer.

7 · Le bloc, et l'indentation

Tout ce qui est entre { et } forme un bloc. On le décale de deux espaces vers la droite — ce qu'on appelle l'indentation : 

if (age >= 18) {
  console.log("Majeur");
  console.log("Bienvenue");
}

L'indentation ne change rien pour le navigateur — mais tout pour vous. Un code mal décalé rend les erreurs d'accolades presque introuvables. VSCode le fait pour vous : Maj+Alt+F reformate le fichier entier.
