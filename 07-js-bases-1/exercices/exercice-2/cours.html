Vos premières fonctions

Ce que vous allez apprendre ici : regrouper des instructions dans un bloc nommé, qu'on rappelle autant de fois qu'on veut — et récupérer son résultat.

1 · Le problème que résout une fonction

Imaginez trois calculs de TVA à faire dans votre programme. Sans fonction, vous écrivez trois fois la même chose : 

const prixA = 24 * 1.2;
const prixB = 39 * 1.2;
const prixC = 12 * 1.2;

Si le taux change, vous devez modifier trois lignes — et si vous en oubliez une, rien ne vous prévient. Une fonction règle ce problème : on écrit le calcul une fois, on lui donne un nom, et on l'appelle.

2 · Déclarer une fonction

function addition(a, b) {
  return a + b;
}
Le morceauSon rôle
function« je déclare une fonction »
additionson nom, choisi par vous
(a, b)ses paramètres — les valeurs qu'elle attend
{ … }son corps : ce qu'elle fait
returnce qu'elle renvoie à celui qui l'appelle

Déclarer ne fait rien. Écrire une fonction, c'est écrire une recette : tant que personne ne l'exécute, il ne se passe rien. Vous pouvez recharger la page cent fois, la fonction seule n'affichera jamais rien.

3 · Appeler une fonction

addition(5, 3)     → 8

Les parenthèses sont ce qui déclenche l'exécution. Les valeurs qu'on met dedans s'appellent les arguments : elles viennent se ranger dans les paramètres, dans l'ordre.

À la déclarationÀ l'appel
function addition(a, b)addition(5, 3)
a est un paramètre5 est un argument
un nom d'emplacementla valeur qui s'y range

Sans parenthèses, rien ne s'exécute. Écrire addition seul ne fait pas le calcul : cela désigne la fonction elle-même. La console répond alors par son code source, ce qui déroute souvent. typeof addition répond d'ailleurs "function".

4 · return — la valeur qui ressort

return met fin à la fonction et renvoie une valeur. On peut la ranger dans une boîte, l'afficher, ou la réutiliser dans un calcul : 

const total = addition(5, 3);        // total vaut 8
console.log(addition(10, 2));        // affiche 12
const double = addition(4, 4) * 2;   // 16

Une fonction sans return renvoie undefined. C'est l'erreur la plus fréquente du débutant : 

function rate(a, b) {
  a + b;          ← calculé… puis jeté
}
rate(5, 3)        → undefined

Le calcul a bien eu lieu, mais son résultat n'a été donné à personne. Sans return, la valeur est perdue.

Après return, plus rien

function exemple() {
  return "premier";
  console.log("jamais affiché");   ← ligne morte
}

return sort de la fonction immédiatement. Tout ce qui suit dans le même bloc est ignoré.

5 · Afficher n'est pas renvoyer

La confusion à éviter absolument. Comparez : 

function versConsole(a, b) {
  console.log(a + b);      ← AFFICHE, ne renvoie rien
}

function versAppelant(a, b) {
  return a + b;            ← RENVOIE, n'affiche rien
}

La première parle à l'écran. La seconde donne sa valeur au programme, qui en fait ce qu'il veut. Seule la seconde est réutilisable dans un calcul : 

versConsole(2, 2) * 10     → NaN        rien à multiplier
versAppelant(2, 2) * 10    → 40         ✅

6 · Quand les arguments ne correspondent pas

JavaScript est très permissif — et c'est une source de bogues silencieux :

AppelRésultatPourquoi
addition(5, 3) 8 le cas normal
addition(5) NaN b n'a rien reçu : il vaut undefined
addition(5, 3, 99) 8 l'argument en trop est ignoré, sans erreur
addition("5", 3) "53" ⚠️ le + assemble au lieu d'additionner

La dernière ligne doit vous rappeler quelque chose. C'est le piège du projet 6 : un texte qui entre dans un calcul le transforme en assemblage. Une fonction ne vous en protège pas — convertissez avant d'appeler.

7 · Ce qui vit dans la fonction y reste

function calcul() {
  const interne = 42;
  return interne;
}

calcul()    → 42
interne     → ReferenceError: interne is not defined

Une boîte créée dans une fonction n'existe pas à l'extérieur. C'est une protection : deux fonctions peuvent utiliser le même nom de variable sans se gêner.
