function categorie(age) {
  if (age < 12) {
    return "enfant";
  } else if (age < 18) {
    return "jeune";
  } else if (age < 65) {
    return "adulte";
  } else {
    return "senior";
  }
}

Les quatre choses à retenir

1 · Le piège de l'intervalle

C'est le défaut le plus dangereux de tout le projet. Le visiteur a 70 ans : il n'est pas entre 18 et 65. La bonne réponse est false. Et pourtant : 

18 <= age < 65        → true      ⚠️ faux, sans erreur

JavaScript ne lit pas l'intervalle comme un tout. Il enchaîne deux comparaisons, de gauche à droite : 

1.  18 <= 70      → true
2.  true < 65     → true      (true vaut 1 dans un calcul)

À la deuxième étape, la question posée a purement disparu : on ne compare plus un âge, on compare un booléen à 65. Le résultat n'a plus aucun sens — mais il est valide, donc aucune erreur n'apparaît.

La forme correcte répète la variable de chaque côté : 

age >= 18 && age < 65    → false    ✅

2 · else if : le premier cas vrai gagne

Dans une chaîne if / else if / else, dès qu'une condition est satisfaite, son bloc s'exécute et tout le reste est sauté — les conditions suivantes ne sont même pas évaluées.

C'est ce qui rend l'ordre décisif. Avec age < 18 placé avant age < 12 : 

categorie(8)    → "jeune"      au lieu de "enfant"

Un enfant de 8 ans satisfait déjà age < 18. Le cas « enfant » devient inatteignable : du code mort, que rien ne signale. Toujours du plus restrictif au plus large.

3 · Combiner : et, ou, non

ÉcritureSe litVrai quand…
a && ba et bles deux sont vrais
a || ba ou bau moins un est vrai
!anon aa est faux

À l'étape 7, age vaut 70 (donc pas moins de 12) et estEtudiant est false : le « et » est faux, le « ou » l'est aussi. gratuit vaut false, et !gratuit vaut true.

4 · Les parenthèses ne sont pas décoratives

&& est évalué avant ||, comme la multiplication avant l'addition : 

true || false && false      → true
(true || false) && false    → false

Dans l'étape 7, les parenthèses ne changent pas le résultat — mais elles rendent l'intention lisible. Ne retenez pas la règle de priorité : mettez des parenthèses, elles ne coûtent rien.
