Enchaîner les décisions

Ce que vous allez apprendre ici : enchaîner plusieurs cas avec else if, et combiner des conditions avec et, ou, non.

1 · Plus de deux cas

À l'exercice 1, vous aviez deux chemins : majeur ou mineur. Mais un tarif de médiathèque en compte quatre — enfant, jeune, adulte, senior. Écrire quatre if séparés ne marche pas bien : 

if (age < 12)  { … }
if (age < 18)  { … }   ← un enfant de 8 ans passe AUSSI ici
if (age < 65)  { … }   ← et ici

Chaque if est examiné séparément, donc plusieurs blocs s'exécutent. Ce n'est pas ce qu'on veut.

2 · else if — une seule porte s'ouvre

if (age < 12) {
  console.log("enfant");
} else if (age < 18) {
  console.log("jeune");
} else if (age < 65) {
  console.log("adulte");
} else {
  console.log("senior");
}

La règle tient en une phrase : le premier cas vrai gagne, les autres ne sont même pas examinés. Dès qu'une condition est satisfaite, JavaScript exécute son bloc et saute tout le reste de la chaîne.

C'est pourquoi age < 18 ne piège pas les enfants de 8 ans : ils ont déjà été servis par le premier cas.

L'ordre change tout

Écrivez la même chaîne dans le mauvais ordre, et des cas deviennent inatteignables : 

if (age < 65) {
  console.log("adulte");
} else if (age < 18) {   ← JAMAIS atteint
  console.log("jeune");
}

Avec age = 15, la première condition est déjà vraie : le résultat est "adulte". La ligne "jeune" est du code mort, et aucune erreur ne le signale.

La règle : du cas le plus restrictif au plus large.

4 · Le piège de l'intervalle

C'est le défaut le plus dangereux de ce cours, parce qu'il ne produit aucune erreur. En mathématiques on écrit : 

18 ≤ age < 65

Transcrit tel quel en JavaScript, cela donne un résultat absurde : 

const age = 70;
18 <= age < 65        → true      ⚠️ FAUX, et pourtant accepté

Pourquoi ? JavaScript lit de gauche à droite, en deux temps : 

18 <= 70        → true
true < 65       → true     (true est converti en 1, et 1 < 65)

Le résultat final n'a plus aucun rapport avec la question posée. Un senior de 70 ans est classé « adulte », silencieusement.

Et voici le plus troublant : cette écriture répond true quel que soit l'âge. Essayez avec 8, avec 200 : toujours true. 

age = 70  →  18 <= 70 donne true,  puis true < 65  → true
age = 8   →  18 <= 8  donne false, puis false < 65 → true

Dans les deux cas, la deuxième comparaison porte sur un booléen, pas sur un âge — et true vaut 1, false vaut 0, tous deux inférieurs à 65. Ce test ne se trompe pas de réponse : il ne pose plus aucune question.

La forme correcte répète la variable de chaque côté : 

age >= 18 && age < 65    → false    ✅

5 · Quand un côté suffit : le court-circuit

JavaScript s'arrête dès qu'il connaît la réponse. Avec &&, si le côté gauche est faux, le droit n'est même pas évalué — le résultat est déjà joué : 

false && …    → false    la droite est ignorée
true  || …    → true     la droite est ignorée

Ce n'est pas une curiosité : cela permet de tester quelque chose avant de s'en servir. Vous en verrez l'usage au projet 9.

6 · La priorité : && passe avant ||

true || false && false      → true
(true || false) && false    → false

Comme la multiplication passe avant l'addition en mathématiques, && est évalué avant ||. Les deux lignes ci-dessus donnent des résultats différents.

Ne retenez pas cette règle : mettez des parenthèses. Elles ne coûtent rien, lèvent toute ambiguïté, et rendent votre intention lisible par la personne qui relira votre code — vous, dans trois mois.

7 · Et toujours : convertir avant de comparer

Le piège du projet 6 ne disparaît pas parce qu'on combine les conditions : 

const saisie = prompt("Votre âge ?");     // du TEXTE

Comparer ce texte à un nombre fonctionne — et pas par hasard : JavaScript convertit alors le texte en nombre, systématiquement. "30" >= 18 est vrai, "8" >= 18 est faux, comme on l'attend. Mais dès que les deux côtés sont du texte, la comparaison devient alphabétique — et le résultat bascule : 

saisie < "9"            ⚠️ avec saisie = "10", c'est VRAI
Number(saisie) < 9      ✅ avec saisie = "10", c'est faux

C'est le piège de l'exercice 1, section 6 : "10" < "9" est vrai, car "1" vient avant "9" dans l'ordre du dictionnaire.

La règle sûre : convertissez une fois, dans une boîte, dès la saisie — et ne travaillez plus qu'avec le nombre. Vous ne dépendrez plus des conversions automatiques, que vous ne contrôlez pas.
