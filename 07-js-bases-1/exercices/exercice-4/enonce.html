🎯 Objectif — Écrire un vrai petit programme, en assemblant tout ce que vous savez depuis le projet 6.

🎓 Exercice de synthèse : aucune notion nouvelle. Si une étape vous bloque, la réponse est dans un exercice précédent — le cours vous dit lequel.

Un seul fichier : exercices/exercice-4/app.js

La page travail.html reste figée : n'y touchez pas.

Ce jeu vous parle de deux façons. Une boîte de dialogue pour le joueur, et la console pour vous, le développeur.

Gardez les deux sous les yeux : le nombre secret est affiché dans la console volontairement, sans quoi vous ne pourriez pas tester vos cas.

✅ Le travail — 10 étapes

Partie 1 — les réglages

  1. Créer MINIMUM valant 1 et MAXIMUM valant 10, avec le mot-clé qui interdit le changement

Partie 2 — tirer le nombre secret

  1. Écrire tirerSecret() — sans paramètre — qui renvoie un entier au hasard de MINIMUM à MAXIMUM, dans le cas où MINIMUM vaut 1 : reprenez la formule du projet 6 en remplaçant le 10 par MAXIMUM et le 1 par MINIMUM
  2. Ranger dans secret le résultat de tirerSecret()
  3. Afficher dans la console le texte [triche] le secret est : puis secret

Partie 3 — demander et convertir

  1. Ranger dans saisie la réponse à la question Devinez un nombre entre 1 et 10
  2. Ranger dans proposition la saisie convertie en nombre
  3. Afficher dans la console, en une seule instruction : saisie :, puis saisie, puis → proposition :, puis proposition

L'étape 6 est le point critique du jeu. prompt() rend du texte, le secret est un nombre. Sans conversion, la comparaison de l'étape 8 serait fausse à tous les coups — un joueur qui trouve perdrait quand même, sans la moindre erreur rouge.

Partie 4 — décider

  1. Écrire reponse(proposition) qui renvoie, dans cet ordre : Ce n'est pas un nombre. si ce n'en est pas un, Gagné ! si c'est le secret, Trop petit. si c'est plus petit, Trop grand. sinon
  2. Afficher le message dans une boîte d'alerte, en appelant reponse(proposition)
  3. Afficher dans la console, en une seule instruction : Proposition :, proposition, · Secret :, secret, · Verdict :, reponse(proposition)

L'ordre des cas de l'étape 8 n'est pas libre. Le test « pas un nombre » doit venir en premier. Placé plus bas, il ne serait jamais atteint — c'est la leçon de l'exercice 3, appliquée.

🔍 Comment vérifier

Lisez d'abord le secret dans la console, puis rechargez et répondez volontairement de chaque façon. Vous devez obtenir :

Vous répondez proposition vaut La boîte affiche
le bon nombre ce nombre Gagné !
un nombre plus petit ce nombre Trop petit.
un nombre plus grand ce nombre Trop grand.
abc NaN Ce n'est pas un nombre.
rien du tout, puis OK 0 Trop petit.
Annuler 0 Trop petit.

Les deux dernières lignes surprennent — et elles sont normales. Une saisie vide et une annulation donnent toutes deux 0 une fois converties. Votre jeu ne peut pas les distinguer d'une vraie proposition de zéro.

Ce n'est pas un défaut de votre code, c'est une limite de cette version du jeu. La solution l'explique, et le projet 8 donnera de quoi la corriger.

Ce que vous vérifiez Ce que vous devez constater
Le tirage fonctionne Rechargez dix fois : le secret change, et reste toujours entre 1 et 10
La conversion L'étape 7 montre saisie : "7" (avec guillemets) et proposition : 7 (sans)
Les quatre verdicts Les quatre premiers cas du tableau ci-dessus se comportent bien
Une seule écriture du tirage Math.random n'apparaît qu'une fois, dans tirerSecret
Aucun oubli Ctrl+F sur « TODO » dans app.js : aucun résultat

🧪 Manip — pourquoi convertir change tout

Sur la page de travail, ouvrez la console et tapez ces deux lignes :

  1. "10" < "9" → false
  2. Number("10") < 9 → true

Deux textes se comparent caractère par caractère, comme dans un dictionnaire : le "1" de "10" vient avant "9", et JavaScript s'arrête là. Sans conversion, votre jeu dirait « trop grand » pour un 10 face à un 9.

🏁 Comment savoir que j'ai fini

  • Les quatre verdicts s'affichent correctement, sans erreur rouge
  • Vous savez expliquer pourquoi Number() est indispensable à l'étape 6
  • Vous savez pourquoi le test « pas un nombre » doit être le premier
  • Aucun TODO ne subsiste dans app.js

45 à 55 minutes. C'est l'exercice le plus long du projet, mais aussi le plus gratifiant : à la fin, vous aurez un programme qui joue.
