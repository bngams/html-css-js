Le fichier complet

Afficher app.js en entier 
const MINIMUM = 1;
const MAXIMUM = 10;

function tirerSecret() {
  return Math.floor(Math.random() * MAXIMUM) + MINIMUM;
}

const secret = tirerSecret();

console.log("[triche] le secret est :", secret);

const saisie = prompt("Devinez un nombre entre 1 et 10");
const proposition = Number(saisie);

console.log("saisie :", saisie, "→ proposition :", proposition);

function reponse(proposition) {
  if (isNaN(proposition)) {
    return "Ce n'est pas un nombre.";
  } else if (proposition === secret) {
    return "Gagné !";
  } else if (proposition < secret) {
    return "Trop petit.";
  } else {
    return "Trop grand.";
  }
}

alert(reponse(proposition));

console.log("Proposition :", proposition, "· Secret :", secret,
            "· Verdict :", reponse(proposition));

Les quatre choses à retenir

1 · Tout vient des exercices précédents

Ce programme n'introduit rien. Il assemble — et c'est exactement ce que fait un développeur :

2 · Number() n'est pas une précaution, c'est le cœur du jeu

Sans la conversion de l'étape 6, la comparaison de l'étape 8 serait fausse à tous les coups : 

"7" === 7           → false     le joueur trouve… et perd
Number("7") === 7   → true      ✅

Et aucune erreur rouge n'apparaîtrait. Le jeu marcherait, refuserait toutes les bonnes réponses, et rien n'indiquerait pourquoi. C'est le fil rouge de tout le projet 7 : un type mal converti ne plante pas, il ment.

3 · L'ordre des cas, encore

Le test isNaN doit venir en premier. Placé plus bas, il ne serait jamais atteint — pour une raison particulière : 

NaN === NaN     → false
NaN < 7         → false
NaN > 7         → false

NaN n'est égal à rien, pas même à lui-même, et toutes les comparaisons le concernant sont fausses. Sans le test en tête, une saisie abc tomberait dans le else final et s'entendrait répondre « Trop grand. »

4 · Le défaut assumé : l'annulation

Annuler donne « Trop petit. » — c'est mesurable, et c'est logique : 

prompt annulé      → null
Number(null)       → 0        un nombre parfaitement valide
0 < secret         → vrai     donc "Trop petit."

Valider sans rien taper produit le même effet : Number("") vaut également 0.

Votre jeu ne peut donc pas distinguer « le joueur propose 0 » de « le joueur renonce ». Ce n'est pas une faute de votre part : c'est une limite de cette version, et la reconnaître fait partie du métier.

La corriger demande un test supplémentaire sur saisie avant la conversion — et, pour redemander plutôt que d'abandonner, une boucle : c'est le projet 8.

🎓 Ce que vous savez faire, à la fin du projet 7

  • Écrire une condition if / else correcte
  • Choisir === et savoir pourquoi == est piégeux
  • Écrire une fonction avec des paramètres et un return
  • Distinguer afficher et renvoyer
  • Enchaîner des cas avec else if, du plus restrictif au plus large
  • Combiner des conditions avec &&, ||, !
  • Reconnaître qu'un intervalle s'écrit en deux comparaisons
  • Assembler tout cela en un programme qui tourne
