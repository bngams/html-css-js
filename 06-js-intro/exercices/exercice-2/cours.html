Projet 6 · Exercice 2

Parler à l'utilisateur

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : les quatre façons de communiquer avec le visiteur — trois boîtes de dialogue et la console — et surtout ce que chacune vous renvoie.

1 · Quatre outils, deux usages

À l'exercice 1, vous tapiez dans la console et elle vous répondait. Ici, c'est votre code qui parle, et parfois qui écoute.

Instruction Ce qu'elle fait Pour qui
alert() Affiche un message dans une boîte, avec un bouton OK le visiteur
confirm() Pose une question, avec OK et Annuler le visiteur
prompt() Pose une question avec un champ de saisie le visiteur
console.log() Écrit dans la console — invisible sur la page vous, le développeur

La distinction est importante. Les trois premières interrompent le visiteur : la page se fige tant qu'il n'a pas cliqué. console.log(), lui, ne dérange personne — il sert à vous, pour savoir ce que fait votre code.

2 · alert() — afficher un message

alert("Bonjour !");

Une boîte s'ouvre, le visiteur lit, il clique sur OK, et le programme continue. C'est tout.

alert() ne renvoie rien — sa valeur de retour est undefined. Si vous tapez alert("Salut") dans la console, vous verrez la boîte, puis undefined s'affichera après votre clic. Ce n'est pas une erreur, c'est la réponse normale d'une instruction qui agit sans rien retourner — exactement ce que vous avez vu à l'exercice 1.

3 · confirm() — poser une question fermée

confirm("Voulez-vous continuer ?");

Deux boutons, donc deux réponses possibles, et cette fois la valeur de retour est utile :

Le visiteur clique confirm() renvoie
OK true
Annuler (ou Échap) false

true et false sont les deux seules valeurs d'un nouveau type : le booléen. Vous en ferez un usage constant à partir du projet 7, quand vous écrirez des conditions.

4 · prompt() — demander une saisie

prompt("Comment vous appelez-vous ?");

Une boîte avec un champ de texte. On peut proposer une valeur par défaut en deuxième argument : 

prompt("Votre ville ?", "Toulouse");

Le piège central de cet exercice. prompt() renvoie toujours du texte — même si le visiteur tape des chiffres.

Si on saisit 25, ce que vous recevez n'est pas le nombre 25 mais la chaîne "25". Et vous savez déjà, depuis l'exercice 1, ce que fait le + avec du texte : 

"25" + 1          → "251"     (assemblage, pas addition)
Number("25") + 1  → 26        (conversion, puis addition)

Number() convertit un texte en nombre. C'est la réponse au problème, et vous l'utiliserez dans cet exercice.

Et si le visiteur annule ?

prompt() renvoie alors null — un mot qui signifie « rien du tout », et qui n'est pas la même chose qu'un texte vide :

Le visiteur prompt() renvoie Type
tape 25 puis OK "25" texte
clique OK sans rien taper "" (texte vide) texte
clique Annuler null « rien »

À retenir simplement pour aujourd'hui : annuler ne donne pas un texte vide. Vous apprendrez à traiter ce cas au projet 7, avec les conditions. Ici, il suffit de savoir que cela existe.

5 · console.log() — votre outil de travail

console.log("Le script a bien démarré");
console.log("Âge saisi :", 25);

Rien ne s'affiche sur la page : le message va dans la console, celle que vous avez ouverte à l'exercice 1. On peut lui passer plusieurs valeurs séparées par des virgules — elles s'affichent côte à côte.

C'est l'instruction que vous écrirez le plus souvent de toute votre vie de développeur. Quand un programme ne fait pas ce que vous attendez, la première question est toujours la même : « qu'est-ce qu'il contient, à cet endroit précis ? » — et console.log() répond.

Ne laissez pas vos console.log() dans un site livré. Ils ne dérangent pas le visiteur, mais ils encombrent la console et peuvent révéler des informations internes. On les retire avant la mise en ligne.

Un mot que vous allez voir : let. Il crée une « boîte » nommée, pour garder une valeur et la réutiliser plus loin : 

let prenom = prompt("Comment vous appelez-vous ?");

Dans cet exercice, les boîtes sont déjà créées pour vous : vous n'avez qu'à compléter ce qui suit le signe =. L'exercice 3 y reviendra en détail.

6 · Où écrire ce code ? Le fichier .js

Jusqu'ici vous tapiez dans la console, et tout disparaissait au rechargement. Pour conserver votre code, il faut l'écrire dans un fichier — d'extension .js — et le charger depuis la page : 

<script src="script.js"></script>

Cette ligne est déjà écrite dans la page de l'exercice : vous n'avez qu'à remplir script.js. L'exercice 4 reviendra en détail sur cette balise, et surtout sur où la placer.

La balise <script> a besoin de sa balise fermante, même avec un src. Écrire <script src="…" /> ne fonctionne pas : c'est l'une des exceptions aux balises auto-fermantes vues au projet 1.

Deux détails d'écriture

Détail Ce qu'il faut savoir
Le point-virgule ; Termine une instruction. JavaScript sait souvent s'en passer, mais prenez l'habitude de le mettre : cela évite des surprises.
Les commentaires // sur une ligne et /* sur plusieurs */. Ce ne sont pas ceux du HTML : dans un fichier .js, <!-- … --> ne fonctionne pas.
