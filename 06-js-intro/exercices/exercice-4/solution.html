Avez-vous bien LU l'erreur avant de déplacer la balise ? C'était le cœur de l'exercice. Si vous avez corrigé sans regarder, retournez à la page de travail, remettez la balise dans le <head>, et lisez le message. Il vous servira toute votre carrière.

▶ Voir le corrigé en fonctionnement

Les deux fichiers

1 · Dans travail.html — la balise déplacée

  <p class="message" id="message">En attente du script…</p>

  <!-- … le reste de la page … -->

  <script src="script.js"></script>
</body>

Une seule ligne déplacée, et tout fonctionne. C'est la modification la plus courte du projet — et la plus instructive.

2 · Dans script.js

Afficher script.js en entier 
console.log("script.js chargé");

const titre = document.querySelector("h1");

console.log("Titre trouvé :", titre);

document.querySelector("#compteur").textContent = 47;

document.querySelector("#message").textContent = "emprunts enregistrés aujourd'hui";

Les trois choses à retenir

1 · Le navigateur lit de haut en bas

C'est toute l'explication. Dans le <head>, le <body> n'a pas encore été lu : il n'existe pas. Votre code cherche un <h1> qui n'a pas été créé.

EmplacementquerySelector("h1") renvoie
<head> seulnull
<head> + deferl'élément <h1>
Fin de <body>l'élément <h1>

2 · Chercher est permis, écrire ne l'est pas

Le point le plus subtil de l'exercice. Avec la balise dans le <head>, l'erreur ne désigne pas la ligne qui cherche le titre. Voici ce qui se passe réellement, ligne par ligne :

LigneRésultat
console.log("script.js chargé") ✅ s'affiche
const titre = document.querySelector("h1") ✅ aucune erreur — titre vaut null
console.log("Titre trouvé :", titre) ✅ affiche null
…querySelector("#compteur").textContent = 47 ❌ c'est ici que tout s'arrête

Le message est : TypeError: Cannot set properties of null (setting 'textContent') — « impossible d'écrire dans null ».

Chercher un élément absent est permis : on obtient null. C'est en voulant écrire dedans que le programme s'arrête. Voilà pourquoi l'erreur désigne une ligne qui, elle, est parfaitement correcte.

La leçon de méthode : le numéro de ligne d'une erreur indique où ça casse, pas toujours où est la cause. Ici la cause est dans un autre fichier, et c'est un simple emplacement de balise.

Les erreurs fréquentes

SymptômeCause
TypeError: Cannot set properties of null Deux causes possibles : le script est mal placé, ou le sélecteur ne correspond à rien. Vérifiez l'emplacement d'abord
La console affiche Titre trouvé : null La balise <script> est encore dans le <head>
Rien du tout, pas même le premier message Le fichier n'est pas trouvé : vérifiez le src et le nom exact du fichier. L'onglet Réseau montre une erreur 404
Le compteur affiche 47 mais pas le message L'identifiant message est mal orthographié dans le sélecteur — le dièse est peut-être oublié
La moitié de la page a disparu Vous avez écrit <script src="…" /> : cette balise doit être fermée par </script>
