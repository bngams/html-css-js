Du JavaScript dans une page

Ce que vous allez apprendre ici : comment une page charge son JavaScript, où placer la balise <script>, et pourquoi ce choix décide si votre code fonctionne ou non.

1 · La balise <script>

Depuis l'exercice 2, cette ligne était déjà écrite dans vos pages. La voici enfin expliquée : 

<script src="script.js"></script>
Le morceauSon rôle
<script>« ici, du JavaScript »
src="script.js"le fichier à charger, comme href pour le CSS
</script>la fermeture, obligatoire

La balise fermante n'est pas optionnelle, même avec un src. Écrire <script src="…" /> ne fonctionne pas : tout ce qui suit dans la page serait avalé. C'est l'une des exceptions aux balises auto-fermantes vues au projet 1.

Les deux façons d'écrire du JavaScript

FormeQuand l'utiliser
<script src="script.js"></script>
fichier séparé		 Presque toujours. Réutilisable, relisible, mis en cache par le navigateur
<script> …code… </script>
dans la page		 Dépannage, ou contrainte technique — page unique à envoyer par mail, CMS qui n'accepte qu'un seul fichier

C'est exactement la même distinction qu'au projet 3 entre un fichier style.css et une balise <style> : le fichier séparé est la norme, l'écriture dans la page reste l'exception justifiée.

2 · Le problème : le navigateur lit de haut en bas

Une page est lue ligne par ligne, du haut vers le bas. Quand le navigateur rencontre un <script>, il s'arrête, exécute le code, puis reprend sa lecture.

Conséquence : le code ne peut agir que sur ce qui existe déjà — c'est-à-dire ce qui se trouve au-dessus de lui.

L'expérience

Une même page, un même code, deux emplacements. Le code cherche le titre <h1> de la page : 

document.querySelector("h1")
Où est le <script> Ce que trouve le code
Dans le <head> null — rien du tout
À la fin du <body> Le titre, et son texte "Bonjour"

Dans le <head>, le <body> n'existe pas encore. Le navigateur ne l'a pas lu. Votre code cherche un élément qui n'a pas été créé, et reçoit null.

C'est la cause d'erreur numéro un chez les débutants en JavaScript, et elle n'a rien d'évident : le code est juste, l'emplacement est faux.

3 · La solution la plus simple : tout en bas

<body>

  <h1>Bonjour</h1>
  <p>Le contenu de la page…</p>

  <script src="script.js"></script>
</body>

Juste avant </body>. Tout le contenu a été lu, donc tout existe. C'est la place que vos pages utilisaient depuis l'exercice 2.

Un second avantage : le visiteur voit la page apparaître pendant que le script se charge, au lieu d'attendre devant un écran blanc.

L'autre solution : defer

On peut garder la balise dans le <head> à condition d'ajouter defer : 

<script defer src="script.js"></script>

defer signifie « charge ce fichier maintenant, mais ne l'exécute qu'une fois la page lue ». Le code retrouve alors le titre, comme en fin de <body>.

EmplacementLe code trouve le titre ?
<head> seul❌ null
<head> + defer✅ oui
Fin de <body>✅ oui

Laquelle choisir ? Les deux sont correctes et vous rencontrerez les deux. Pour cette formation, retenez la fin du <body> : c'est la plus simple à comprendre, puisque la raison est visible dans l'ordre des lignes.

4 · Toucher à la page : un avant-goût

Jusqu'ici votre code parlait au visiteur (alert) ou à vous (console.log). Il peut aussi modifier la page : 

document.querySelector("h1").textContent = "Nouveau titre";
Le morceauSon rôle
documentla page entière
.querySelector("h1")« trouve le premier h1 » — un sélecteur CSS, comme au projet 3
.textContentle texte affiché dans cet élément
= "…"on le remplace

Vous savez déjà écrire des sélecteurs. querySelector accepte exactement les mêmes qu'en CSS : "h1", ".carte", "#total". Tout le projet 9 sera consacré à cette manipulation de la page.

Si l'élément n'existe pas, querySelector renvoie null, et tenter de le modifier arrête le programme : 

TypeError: Cannot set properties of null

Quand vous voyez ce message, posez-vous deux questions : le sélecteur est-il juste ? et surtout, le script est-il au bon endroit ?
