Des variables et des calculs

Ce que vous allez apprendre ici : ranger des valeurs dans des variables, savoir de quel type elles sont, et faire des calculs fiables avec l'objet Math.

1 · let — une boîte nommée

Vous avez déjà utilisé let à l'exercice 2, sans l'étudier. Voici ce qui se passe vraiment : 

let prenom = "Camille";
Le morceauSon rôle
let« crée une boîte »
prenomle nom de la boîte, choisi par vous
=« range dedans » — ce n'est pas l'égalité des maths
"Camille"la valeur rangée

Ensuite, le nom remplace la valeur partout où vous l'écrivez :

let prenom = "Camille";
alert("Bonjour " + prenom);     → Bonjour Camille

Changer le contenu

Une boîte créée avec let peut être remplie à nouveau. On ne réécrit pas let : 

let score = 10;
score = 20;          ← on remplace le contenu
score = score + 5;   ← on lit l'ancien, on range le nouveau  → 25

score = score + 5 n'a aucun sens en mathématiques. En programmation, le = se lit toujours de droite à gauche : « calcule score + 5, puis range le résultat dans score ».

2 · const — une boîte qu'on ne peut plus changer

Quand une valeur ne doit jamais changer, on écrit const au lieu de let : 

const TVA = 0.20;
TVA = 0.10;    ← ✋ refusé

Le navigateur répond alors, en rouge :

TypeError: Assignment to constant variable.

Ce n'est pas une punition, c'est une protection. Vous dites au navigateur : « cette valeur est fixe ». S'il vous arrive de la modifier par erreur, il vous arrête tout de suite, au lieu de vous laisser chercher pendant une heure.

Deuxième différence : un const doit recevoir sa valeur immédiatement.

const prix;    ← ✋ SyntaxError: Missing initializer in const declaration

Lequel choisir ?

SituationUtilisez
La valeur ne changera pas (un taux, un nom de site, une limite) const
La valeur va évoluer (un score, un total qu'on additionne) let

La règle des professionnels : const par défaut, et let seulement quand on a besoin de changer la valeur. Cela rend le code plus sûr et plus lisible — on voit d'un coup d'œil ce qui bouge.

3 · Les types de valeurs

À l'exercice 2, la console affichait vos trois valeurs avec des couleurs différentes. Voici pourquoi : chaque valeur a un type. L'instruction typeof vous le dit.

Valeurtypeof répondC'est…
5"number"un nombre
"5""string"du texte
true"boolean"vrai ou faux
undefined"undefined"une boîte jamais remplie

Le type change tout, et vous l'avez déjà vu : "5" et 5 se ressemblent, mais "5" + 1 donne "51" tandis que 5 + 1 donne 6. Quand un calcul donne un résultat absurde, la première question à se poser est celle du type.

4 · Math — la boîte à outils des nombres

Math n'est pas une variable que vous créez : c'est un outil fourni par le navigateur, toujours disponible.

Le hasard

Math.random()      → un nombre entre 0 et 1, par exemple 0.6829…

Seul, il sert rarement. La formule utile, à retenir telle quelle, tire un entier entre 1 et 6 : 

Math.floor(Math.random() * 6) + 1

Pourquoi cette formule ? Math.random() donne un nombre inférieur à 1 — jamais 1 exactement. Multiplié par 6, il reste sous 6. Math.floor le descend à l'entier du dessous : on obtient 0, 1, 2, 3, 4 ou 5. Le + 1 décale enfin la plage sur 1 à 6.

5 · Afficher joliment un nombre décimal

Les nombres à virgule réservent parfois des surprises :

0.1 + 0.2     → 0.30000000000000004

Ce n'est pas un bug de JavaScript : tous les langages font cela, parce qu'un ordinateur stocke les décimaux en binaire. Pour l'affichage, on utilise .toFixed(), qui fixe le nombre de décimales : 

(5.678).toFixed(2)     → "5.68"
(0.1 + 0.2).toFixed(2) → "0.30"

⚠️ Attention au type. Regardez bien les guillemets : .toFixed() renvoie du texte, pas un nombre. 

(5.678).toFixed(2) + 1          → "5.681"     ⚠️ assemblage !
Number((5.678).toFixed(2)) + 1  → 6.68        ✅ addition

C'est exactement le piège de l'exercice 2, sous une autre forme. Retenez la règle : .toFixed() sert à AFFICHER, jamais à calculer.
