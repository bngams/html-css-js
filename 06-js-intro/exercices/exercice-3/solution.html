Les quatre choses à retenir

1 · const protège, let autorise

Le choix n'est pas une question de goût. Il dit au navigateur ce qui a le droit de changer :

VariableMot-cléPourquoi
NOM_MEDIATHEQUE const le nom ne changera jamais
PRIX_ABONNEMENT const le tarif est fixe dans ce programme
nombreEmprunts let il passe de 0 à 3, puis à 4
moyennePages, prixTTC, gagnant… const calculées une fois, jamais modifiées ensuite

Une seule variable méritait let dans tout cet exercice : nombreEmprunts, la seule qui change de valeur. Toutes les autres sont calculées une fois pour toutes — donc const. C'est exactement ce que dit la règle du cours, appliquée.

La règle des professionnels : const par défaut, let seulement quand la valeur doit changer. Un lecteur de votre code voit alors d'un coup d'œil ce qui bouge — et ce qui ne bouge pas.

2 · score = score + 1 n'est pas une équation

À l'étape 5, nombreEmprunts = nombreEmprunts + 1 semble absurde en mathématiques. Le = de la programmation se lit de droite à gauche : 

nombreEmprunts = nombreEmprunts + 1;
                 └──────┬───────┘
                   1. on calcule 3 + 1
                 └──┬──┘
                   2. on range 4 dedans

3 · L'arrondi change réellement la valeur

La moyenne de 312, 247 et 190 vaut 249.66666666666666 — une division qui ne tombe pas juste, comme presque toutes les moyennes. Math.round la ramène à 250.

OutilSur 249.666…Effet
Math.round250au plus proche
Math.floor249toujours en dessous
Math.ceil250toujours au-dessus

4 · .toFixed() renvoie du TEXTE

24 × 1.2 ne donne pas 28.8 mais 28.799999999999997. Ce n'est pas un bug : tous les langages stockent les décimaux en binaire, et certains nombres n'y tombent pas juste.

.toFixed(2) règle l'affichage — mais attention au type : 

prixTTC.toFixed(2)              → "28.80"    du TEXTE
prixTTC.toFixed(2) + 1          → "28.801"   ⚠️ assemblage
Number(prixTTC.toFixed(2)) + 1  → 29.8       ✅ addition

C'est le piège de l'exercice 2 sous une autre forme. La règle : .toFixed() sert à AFFICHER, jamais à calculer.
