Le squelette d'une page HTML

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : les cinq éléments que contient toute page web, sans exception. Une fois ces cinq-là compris, vous pouvez lire le début de n'importe quelle page du web.

Une page HTML, c'est quoi ?

Un fichier texte. Rien d'autre. Ce qui le distingue d'un texte ordinaire, ce sont les balises : des mots entre chevrons qui décrivent le rôle de chaque morceau de contenu.

Une balise s'ouvre et se ferme, et elle entoure le contenu qu'elle décrit :

<p>Ceci est un paragraphe.</p>
 ↑                          ↑
 ouverture              fermeture (avec /)

Le navigateur lit ces balises et en déduit comment afficher la page. Il n'affiche jamais les balises elles-mêmes — seulement leur contenu.

Les commentaires : du texte que le navigateur ignore

On peut écrire dans un fichier HTML du texte destiné aux humains uniquement : des notes, des explications, des rappels. Le navigateur les lit, comprend qu'ils ne sont pas du contenu, et ne les affiche pas.

Un commentaire s'ouvre par <!-- et se ferme par --> :

<!-- Ceci est un commentaire : il n'apparaît pas dans la page -->
<p>Ceci est un paragraphe : il apparaît.</p>

Il peut tenir sur plusieurs lignes :

<!--
  Tout ce bloc est ignoré par le navigateur,
  même s'il fait dix lignes.
-->

Vous allez en voir beaucoup. Dans l'onglet « À vous de jouer », les consignes sont écrites en commentaires, directement dans le fichier que vous modifiez. C'est pour cette raison que la page s'affiche vide au départ : elle ne contient que des commentaires, donc le navigateur n'a rien à afficher. À vous d'écrire le vrai contenu à côté.

Un commentaire n'est pas un secret. N'importe qui peut lire le code source d'une page (clic droit → « Afficher le code source »). N'y écrivez jamais un mot de passe ou une information confidentielle.

L'exception : les balises auto-fermantes

Certaines balises ne se ferment pas, et pour une raison simple : elles n'entourent aucun contenu. Elles ne décrivent pas un morceau de texte, elles insèrent quelque chose à un endroit précis.

Comparez. Un paragraphe entoure du texte, donc il a besoin d'un début et d'une fin : 

<p>Ceci est un paragraphe.</p>

<br>, qui force un retour à la ligne, n'entoure rien : il est l'action. Rien à fermer, donc : 

<p>Première ligne<br>Seconde ligne</p>

Il y en a d'autres — vous en écrirez une dès la notion 3 de ce cours (<meta charset="UTF-8">), et le doctype juste en dessous suit la même logique. La liste complète est sur MDN ; inutile de l'apprendre par cœur, vous les reconnaîtrez à l'usage.

1 · Le doctype

Toute première ligne du fichier. Elle annonce au navigateur : « ceci est du HTML moderne ». Sans elle, le navigateur bascule dans un mode de compatibilité ancien où certains styles se comportent bizarrement. 

<!DOCTYPE html>

Particularité : elle commence par un point d'exclamation et ne se ferme pas. C'est la seule ligne de ce genre.

2 · La balise <html> et la langue

Elle enveloppe absolument tout le reste de la page. On lui ajoute un attribut lang qui déclare la langue du contenu. 

<html lang="fr">
  ...tout le contenu de la page...
</html>

À quoi sert lang ? Il n'a aucun effet visible, mais : les lecteurs d'écran prononcent correctement le texte, le navigateur propose la traduction au bon moment, et la césure des mots en fin de ligne suit les règles du français. C'est une ligne gratuite qui rend la page accessible.

Au passage : un attribut, c'est quoi ?

Une information supplémentaire écrite dans la balise ouvrante, sous la forme nom="valeur". Ici lang="fr". Vous en verrez beaucoup d'autres.

3 · Le <head> et l'encodage

Le <head> contient les informations invisibles pour le visiteur, mais lues par le navigateur. La plus importante est l'encodage des caractères : 

<head>
  <meta charset="UTF-8">
</head>

Oubliez cette ligne et vos accents cassent. « créé » devient « crÃ©Ã© ». UTF-8 est l'encodage qui couvre les accents français, les emojis et la quasi-totalité des langues du monde. Mettez-le toujours, et le plus haut possible dans le <head>.

Voici la première auto-fermante annoncée plus haut : <meta> insère une information, elle n'entoure rien.

4 · Le <title>

Le titre de la page. Il ne s'affiche pas dans la page elle-même, mais :

  • dans l'onglet du navigateur
  • dans les favoris, si on enregistre la page
  • comme ligne bleue cliquable dans les résultats Google
<head>
  <meta charset="UTF-8">
  <title>Ma première page</title>
</head>

C'est le seul élément du <head> que le visiteur perçoit.

5 · Le <body> : titres et paragraphes

Tout ce que le visiteur voit à l'écran est dans le <body>. Les deux balises de base :

Balise Rôle
<h1> Le titre principal du contenu. Un seul par page. h pour heading (titre).
<p> Un paragraphe de texte. p pour paragraph. 
<body>
  <h1>Ma première page</h1>
  <p>Bonjour, voici mon premier site web.</p>
</body>

Les retours à la ligne que vous tapez ne comptent pas. Le HTML ignore les espaces et sauts de ligne en trop : c'est la balise <p> qui crée la séparation visuelle entre deux paragraphes, pas la touche Entrée.

Tout ensemble

Voici les cinq éléments assemblés — c'est la structure de départ de toute page :

<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8">
  <title>Ma première page</title>
</head>
<body>
  <h1>Ma première page</h1>
  <p>Bonjour, voici mon premier site web.</p>
</body>
</html>

Remarquez l'emboîtement : html contient head et body, qui contiennent eux-mêmes d'autres balises. L'indentation (les décalages) n'est pas obligatoire, mais elle rend cet emboîtement lisible. Prenez l'habitude tout de suite.

La référence

Ressource Pourquoi celle-là
MDN — Introduction à HTML Le cours complet de Mozilla, en français, qui reprend et approfondit tout ce chapitre. Si vous ne gardez qu'un lien, gardez celui-là.

Ressource Pourquoi celle-là

Approfondir

Ressource Pourquoi celle-là
web.dev — Learn HTML Cours structuré de l'équipe Chrome, en anglais. Plus exigeant que MDN, avec un vrai accent sur les bonnes pratiques modernes.

Un mot sur W3Schools. C'est souvent le premier résultat Google, c'est pratique pour un exemple rapide, mais le site n'a aucun lien avec le W3C malgré son nom, et il contient des imprécisions ou des conseils dépassés. En cas de doute, vérifiez sur MDN.
