Projet 1 · Exercice 3

Images et contenus embarqués

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : insérer dans une page ce qu'on ne tape pas au clavier — des images, un dessin, une vidéo, une carte, un document.

Toutes ces balises ont un point commun : elles pointent vers un fichier. La notion de chemin devient donc centrale — c'est par elle qu'on commence.

1 · Les chemins : dire où se trouve un fichier

Jusqu'ici vos pages se suffisaient à elles-mêmes. Dès qu'on insère une image, il faut indiquer où elle est rangée par rapport à la page qui l'affiche.

Imaginons ce rangement :

exercice-3/
├── travail.html        ← votre page
└── images/
    └── photo.svg       ← l'image
Écriture Sens
photo.svg Dans le même dossier que la page
images/photo.svg Descendre dans le sous-dossier images
../photo.svg Remonter d'un dossier (deux points)
../../assets/photo.svg Remonter deux fois, puis descendre dans assets

../ se lit « le dossier au-dessus ». On peut l'enchaîner autant de fois qu'il le faut. C'est l'écriture que vous utiliserez dans cet exercice, car les images sont rangées dans un dossier assets/ commun à tout le projet — pas à côté de votre page.

Un chemin faux ne déclenche aucun message d'erreur. L'image ne s'affiche simplement pas. C'est la première chose à vérifier quand une image reste invisible — bien avant de soupçonner le fichier lui-même.

2 · Les images — <img>

Une balise auto-fermante (elle n'entoure rien), avec deux attributs obligatoires : 

<img src="../../assets/photo.svg" alt="Un paysage de collines vertes">
Attribut Rôle
src source : le chemin du fichier image
alt alternative : le texte qui remplace l'image

Pourquoi alt n'est pas optionnel

Ce texte sert dans trois situations, et deux d'entre elles sont quotidiennes :

  • l'image ne charge pas (chemin erroné, fichier absent, connexion coupée) — le texte s'affiche à la place ;
  • une personne aveugle visite la page — son lecteur d'écran lit ce texte à voix haute ;
  • un moteur de recherche indexe la page — il ne « voit » que ce texte.

Comment l'écrire : décrivez ce que l'image montre, en une courte phrase. Ne commencez pas par « image de » — le lecteur d'écran annonce déjà qu'il s'agit d'une image.

✅ alt="Un paysage de collines vertes sous un soleil jaune"
❌ alt="photo" · ❌ alt="image de paysage" · ❌ alt="IMG_4523.jpg"

3 · Une image avec sa légende — <figure>

Quand une image s'accompagne d'une légende visible, on relie les deux explicitement : 

<figure>
  <img src="../../assets/photo.svg" alt="Un paysage de collines vertes">
  <figcaption>Illustration d'exemple, dessinée en SVG.</figcaption>
</figure>

alt et figcaption ne font pas double emploi. alt décrit l'image pour qui ne la voit pas ; figcaption la commente pour tout le monde. Une légende qui se contente de répéter l'alt n'apporte rien.

4 · Un dessin dans la page — <svg>

Un SVG n'est pas une photo : c'est un dessin décrit par des formes (cercles, rectangles, traits). Conséquence pratique : il reste net à n'importe quelle taille, là où une photo agrandie devient floue.

Il peut s'écrire directement dans le HTML, sans fichier séparé :

<svg width="120" height="120" viewBox="0 0 120 120"
     role="img" aria-label="Un cercle bleu">
  <circle cx="60" cy="60" r="50" fill="#0b6bcb" />
</svg>
Ce qu'on écrit Ce que ça veut dire
cx · cy La position du centre du cercle (x = horizontal, y = vertical)
r Le rayon
fill La couleur de remplissage
role + aria-label Jouent ici le rôle de l'alt d'une image

5 · Une vidéo — <video>

<video src="film.mp4" controls width="400">
  Votre navigateur ne sait pas lire les vidéos.
</video>

controls s'écrit seul, sans = ni valeur. C'est un attribut booléen : sa seule présence suffit. Sans lui, aucun bouton lecture/pause n'apparaît et le visiteur ne peut rien faire.

Le texte placé entre <video> et </video> ne s'affiche que si le navigateur ne sait pas lire la vidéo. C'est un filet de sécurité, pas une légende.

6 · Une page dans la page — <iframe>

Une iframe affiche une autre page web à l'intérieur de la vôtre. C'est ce qu'utilisent les cartes, les vidéos YouTube, les lecteurs de musique embarqués. 

<iframe src="https://exemple.fr/carte"
        width="600" height="300"
        title="Carte du centre-ville"></iframe>

width et height s'écrivent en nombres simples, sans unité : width="600" signifie 600 pixels. Écrire width="100%" est une erreur que le validateur du W3C signale — les pourcentages relèvent du CSS, que vous verrez au projet 3.

L'attribut title est important ici — et ce n'est pas le même que le <title> de la page. Sans lui, une personne utilisant un lecteur d'écran entend seulement « cadre », sans savoir ce qu'il contient.

7 · Un document — un simple lien

Un PDF ne demande aucune balise particulière : c'est un lien, comme ceux de l'exercice 2. Le navigateur l'ouvre dans sa visionneuse intégrée. 

<a href="../../assets/programme.pdf" target="_blank" rel="noopener">
  Le programme (PDF)
</a>

Signalez le format dans le texte du lien — « (PDF) ». Le visiteur sait ainsi à quoi s'attendre avant de cliquer : un document qui s'ouvre dans une visionneuse, pas une page web.
