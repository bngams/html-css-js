Projet 10 · Exercice 3

Un formulaire qui ne recharge pas

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Avez-vous essayé la manip sans preventDefault ? C'est elle qui montre que votre code s'exécute bien — et que le rechargement efface tout juste après. Si ce n'est pas fait, retournez à la page de travail.

▶ Voir le corrigé en fonctionnement

Le fichier complet

Une solution possible. Seuls les critères comptent : une autre écriture qui les remplit tous est tout aussi juste.

Afficher app.js en entier 
const emprunts = [
  { titre: "Dune",              lecteur: "Karim" },
  { titre: "Fondation",         lecteur: "Léa" },
  { titre: "Les Fourmis",       lecteur: "Tomas" }
];

/* 1 · Les éléments de la page */

const form     = document.querySelector("#ajout");
const champT   = document.querySelector("#titre");
const champL   = document.querySelector("#lecteur");
const liste    = document.querySelector("#liste");
const compteur = document.querySelector("#compteur");
const message  = document.querySelector("#message");

/* 2 · La fonction qui reconstruit la liste */

function afficher() {

  for (const ancien of liste.querySelectorAll("li")) {
    ancien.remove();
  }

  for (const emprunt of emprunts) {

    const li = document.createElement("li");
    li.classList.add("emprunt");

    const titre = document.createElement("span");
    titre.classList.add("emprunt__titre");
    titre.textContent = emprunt.titre;

    const lecteur = document.createElement("span");
    lecteur.classList.add("emprunt__lecteur");
    lecteur.textContent = emprunt.lecteur;

    li.append(titre, lecteur);
    liste.append(li);
  }

  compteur.textContent = emprunts.length + " emprunt(s)";
}

/* 3 · Au chargement */

afficher();

console.log("Au départ :", emprunts.length, "emprunt(s)");

/* 4 · À l'envoi du formulaire */

form.addEventListener("submit", function (evenement) {

  evenement.preventDefault();

  const titre   = champT.value.trim();
  const lecteur = champL.value.trim();

  if (titre === "" || lecteur === "") {
    message.textContent = "Remplissez les deux champs.";
    message.classList.add("erreur");

    console.log("Refusé : un champ est vide");
    return;
  }

  emprunts.push({ titre: titre, lecteur: lecteur });

  afficher();

  message.textContent = "« " + titre + " » ajouté.";
  message.classList.remove("erreur");

  champT.value = "";
  champL.value = "";

  console.log("Ajouté :", titre, "→", emprunts.length, "emprunt(s)");
});

Les cinq choses à retenir

1 · L'écouteur sur le <form>

form.addEventListener("submit", …)     ✅
bouton.addEventListener("click", …)    ⚠️ rate la touche Entrée

Le critère 8 est là pour ça. Un écouteur click sur le bouton semble marcher — jusqu'à ce qu'un utilisateur valide au clavier, ce que font la plupart des gens dans un formulaire court.

2 · preventDefault en première ligne

C'est la première instruction de la fonction, avant toute lecture de champ. Sans elle, le reste s'exécute quand même, puis disparaît : 

avec preventDefault  →  la liste s'allonge, l'URL ne bouge pas     ✅
sans preventDefault  →  la page recharge, retour à 3 emprunts      ❌
                        l'URL se termine par un ?
                        la console est vidée

3 · Nettoyer avant de vérifier

const titre = champT.value.trim();     ← on nettoie une fois
if (titre === "") { … }                ← on vérifie le nettoyé
emprunts.push({ titre: titre, … });    ← on stocke le nettoyé

4 · Refuser, c'est aussi s'arrêter

if (titre === "" || lecteur === "") {
  message.textContent = "Remplissez les deux champs.";
  message.classList.add("erreur");
  console.log("Refusé : un champ est vide");
  return;                                  ← indispensable
}

Sans le return, le code poursuit : un emprunt aux champs vides est ajouté, et le message d'erreur est aussitôt remplacé par le message de succès. Le refus ne refuse rien.

Les champs ne sont pas vidés en cas de refus — c'est le critère 10. Effacer ce que l'utilisateur vient de taper au moment où on lui dit que c'est incomplet serait la pire des réponses.

5 · Une classe qu'on pose et qu'on retire

message.classList.add("erreur");      ← au refus
message.classList.remove("erreur");   ← au succès

Le même piège qu'à l'exercice 2 avec la classe vide : une classe ajoutée sans jamais être retirée fige l'apparence. Le message resterait rouge pour toujours après le premier refus.

Les erreurs fréquentes

SymptômeCause
La page clignote, la liste revient à 3, l'URL se remplit preventDefault() manque, ou l'écouteur n'est pas sur le <form> (cours §3)
Le clic marche, la touche Entrée recharge la page L'écouteur est posé sur le bouton en "click" au lieu du formulaire en "submit" (cours §2)
Un emprunt vide est ajouté après le message d'erreur Le return manque dans le if (cours §7)
Trois espaces sont acceptés comme un titre .trim() manque : " " n'est pas "" (cours §6)
Le message reste rouge après un ajout réussi La classe erreur est ajoutée, jamais retirée
Les emprunts s'ajoutent en double à chaque envoi La liste n'est pas vidée avant d'être reconstruite (projet 9, exercice 4)
