Projet 10 · Exercice 3

Un formulaire qui ne recharge pas

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

🎯 Objectif — Un formulaire qui ajoute un emprunt à la liste sans recharger la page, et qui refuse les saisies vides.

Prérequis : les exercices 1 et 2 de ce projet, et le projet 9 (créer, insérer, vider).

Un seul fichier : exercices/exercice-3/app.js

Le tableau de données — trois emprunts — vous est fourni. Contrairement aux exercices précédents, il va grandir.

Essayez le formulaire AVANT d'écrire une ligne.

Tapez un titre, appuyez sur Entrée : la page se recharge, l'URL se termine par un ?, et rien n'est enregistré. C'est le comportement par défaut que votre code doit couper (cours §1 et §3).

✅ Les critères d'acceptation

Au chargement

  1. Les trois emprunts du tableau sont affichés. Chaque ligne porte la classe emprunt et contient deux éléments : le titre (emprunt__titre) et le lecteur (emprunt__lecteur)
  2. Le compteur affiche 3 emprunt(s)

Quand on envoie le formulaire

  1. La page ne se recharge pas. L'URL reste inchangée et la console garde ses messages
  2. L'emprunt est ajouté au tableau et la liste est reconstruite : une ligne de plus, dans l'ordre d'ajout
  3. Le compteur suit : N emprunt(s)
  4. Les deux champs sont vidés après un ajout réussi
  5. Le message affiche « Titre » ajouté. — avec les guillemets français — et ne porte pas la classe erreur
  6. L'envoi fonctionne aussi bien au clic sur le bouton qu'avec la touche Entrée depuis un champ

Quand la saisie est incomplète

  1. Si l'un des deux champs au moins est vide, rien n'est ajouté : ni au tableau, ni à la liste, et le compteur ne bouge pas
  2. Le message affiche Remplissez les deux champs. et porte la classe erreur — il devient rouge. Les champs ne sont pas vidés : ce qui a déjà été saisi reste à l'écran
  3. Un champ contenant seulement des espaces compte comme vide (cours §6)
  4. Après un refus, un envoi correct enlève la classe erreur : le message redevient vert

Dans la console

  1. La console affiche, à chaque moment, la ligne attendue :
    • au chargement — Au départ : suivi du nombre d'emprunts, puis du mot emprunt(s)
    • à chaque ajout — Ajouté :, le titre, →, le nouveau total, puis emprunt(s)
    • à chaque refus — Refusé : un champ est vide

🔍 Comment vérifier

Rechargez. Avant toute action, la console affiche exactement cette ligne : 

Au départ : 3 emprunt(s)

Faites ensuite, dans cet ordre : ajoutez Dune Messie / Amina, puis envoyez avec les deux champs vides, puis ajoutez Le Horla / Tomas avec les espaces. La console doit afficher : 

Ajouté : Dune Messie → 4 emprunt(s)
Refusé : un champ est vide
Ajouté : Le Horla → 5 emprunt(s)

La troisième ligne est le test du trim. Si elle affiche Ajouté : Le Horla avec les espaces, ou si la carte créée est décalée dans la page, le nettoyage n'a pas eu lieu.

Et la page doit se comporter ainsi :

au chargement3 videvides
ajout valide4 « Dune Messie » ajouté. — vertvidés
deux champs vides4 (inchangé) Remplissez les deux champs. — rouge vides

Le critère 12 se teste en deux envois. Provoquez un refus (message rouge), puis faites un ajout correct : le message doit redevenir vert. S'il reste rouge, la classe erreur est ajoutée mais jamais retirée (cours §7).

🧪 Manip — sans preventDefault

Une fois l'exercice terminé, essayez volontairement ceci :

  1. Mettez en commentaire la ligne evenement.preventDefault();.
  2. Enregistrez, rechargez, remplissez les deux champs, envoyez.

La page se recharge : la liste revient à trois emprunts, l'URL se termine par un ?, et la console est vidée — vos messages ont disparu. Aucune erreur rouge.

Votre code s'est pourtant bien exécuté : il a ajouté l'emprunt, puis le rechargement a tout effacé. Remettez ensuite la ligne.

🏁 Comment savoir que j'ai fini

  • La page ne clignote jamais à l'envoi
  • Les emprunts s'accumulent, dans l'ordre d'ajout
  • Un champ vide — ou plein d'espaces — est refusé, en rouge
  • Le message redevient vert après un ajout correct
  • Vous savez dire pourquoi l'écouteur se pose sur le <form> et non sur le bouton

⏱️ Durée indicative

50 à 60 minutes. Le cycle complet du cours §5 compte sept étapes. Faites d'abord l'affichage des trois emprunts au chargement, puis l'ajout, et la vérification des champs en dernier.
