Projet 10 · Exercice 3

Un formulaire qui ne recharge pas

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : intercepter l'envoi d'un formulaire, et empêcher le navigateur de recharger la page.

Trois notions nouvelles : l'événement submit, preventDefault() et .trim().

1 · Le navigateur a ses propres réflexes

Jusqu'ici, sans votre code, il ne se passait rien : un bouton inerte reste inerte. Un formulaire, lui, a un comportement par défaut — envoyer ses données et recharger la page.

Essayez avant de lire la suite. Ouvrez la page de travail, tapez un titre, appuyez sur Entrée.

La page clignote, les champs se vident, la console se vide aussi, et l'URL change : elle se termine désormais par un ?. Rien n'a été enregistré.

Ce réflexe date d'avant JavaScript. Le formulaire envoyait les données à un serveur, qui renvoyait une nouvelle page. C'est toujours le comportement par défaut — et c'est celui qu'on remplace.

2 · L'événement submit

form.addEventListener("submit", function (evenement) {
  // …
});
ÉvénementSur quoiQuand
"click"un boutonau clic
"input"un champà chaque frappe
"submit"le <form>à l'envoi

L'écouteur se pose sur le <form>, pas sur le bouton. C'est le formulaire qui est envoyé, pas le bouton qui est cliqué.

L'avantage est concret : submit se déclenche aussi quand on appuie sur Entrée dans un champ, sans toucher au bouton. Un écouteur click sur le bouton raterait ce cas.

3 · preventDefault() — couper le réflexe

La fonction reçoit un paramètre : l'événement lui-même. C'est lui qui porte le moyen d'annuler le comportement par défaut. 

form.addEventListener("submit", function (evenement) {

  evenement.preventDefault();   ← la page ne se rechargera pas

  // votre code prend le relais
});

Le nom du paramètre est libre. Vous verrez souvent e ou event ; ici evenement, pour que ce soit lisible. C'est le premier paramètre qui compte, pas son nom — comme pour n'importe quelle fonction du projet 7.

Sans preventDefault, votre code s'exécute quand même — puis la page se recharge et efface tout. C'est ce qui rend l'erreur déroutante : on voit parfois la liste s'allonger une fraction de seconde avant de disparaître.

4 · Des données qui grandissent

Nouveauté de cet exercice : le tableau n'est plus figé. Chaque envoi valide y ajoute une ligne, avec push du projet 8 : 

emprunts.push({ titre: titre, lecteur: lecteur });

Rappel du projet 8 : push fonctionne même sur un tableau déclaré avec const. On ne remplace pas le tableau, on le modifie — ce que const autorise.

5 · Le cycle complet

1. l'utilisateur envoie   → submit
2. on coupe le réflexe    → preventDefault()
3. on lit les champs      → .value
4. on vérifie             → si vide, on refuse et on s'arrête
5. on ajoute aux données  → push
6. on reconstruit la page → la fonction de l'exercice 2
7. on vide les champs     → .value = ""

L'étape 6 ne change pas d'un iota. C'est exactement la fonction « vider puis reconstruire » de l'exercice 2 et du projet 9. Les données ont changé, l'affichage se refait pareil.

6 · .trim() — enlever les espaces autour

"   Le Horla   ".trim()    → "Le Horla"
"   ".trim()               → ""           ← devient vide !

Sans trim, un visiteur qui tape trois espaces passe la vérification : " " n'est pas une chaîne vide. 

"   " === ""            → false    ⚠️ accepté à tort
"   ".trim() === ""     → true     ✅ refusé

On nettoie avant de vérifier, et on stocke la version nettoyée. Sinon le titre s'afficherait avec ses espaces parasites.

7 · Refuser et s'arrêter

if (titre === "" || lecteur === "") {
  message.textContent = "Remplissez les deux champs.";
  message.classList.add("erreur");
  return;                        ← on sort de la fonction ICI
}

Sans le return, le code continue : un emprunt vide serait ajouté juste après le message d'erreur.

return sans valeur, c'est le « on s'arrête là » du projet 7. Le reste de la fonction n'est pas exécuté.

Et le message doit pouvoir redevenir normal. Si vous ajoutez la classe erreur sans jamais la retirer, le message restera rouge même après un ajout réussi — l'erreur de l'exercice 2 avec la classe vide.

Un seul message pour les deux cas : c'est volontairement simple. Il s'affiche aussi quand un seul des deux champs manque. Un vrai formulaire dirait lequel — c'est le même if, avec deux branches de plus.

8 · ⚠️ Ce qui disparaît au rechargement

Vos ajouts ne survivent pas à un F5. Le tableau vit en mémoire, dans la page ; recharger repart du tableau écrit dans le fichier.

Ce n'est pas un défaut de votre code. Conserver des données demande un serveur ou un stockage — ce n'est pas au programme de ce cours.
