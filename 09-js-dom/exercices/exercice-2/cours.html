Changer ce qu'on a trouvé

Ce que vous allez apprendre ici : les trois façons de modifier un élément — son texte, ses classes, son style — et surtout laquelle choisir.

1 · Trois leviers, trois usages

À l'exercice 1, vous avez appris à trouver. Maintenant, on modifie. Trois outils, et ils ne sont pas interchangeables :

Ce que vous voulez changerL'outil
le texte affiché.textContent
l'apparence, définie en CSS.classList
une propriété CSS précise, à la main.style

La règle du métier, en une phrase : on change la classe, pas le style. La section 5 explique pourquoi, et ce n'est pas qu'une question de goût.

2 · .textContent — changer le texte

Vous le connaissez depuis le projet 6 :

document.querySelector("#compteur").textContent = "5 livres";

Il remplace tout le contenu textuel de l'élément. Ce qui s'y trouvait — y compris d'autres balises — disparaît.

Lire ou écrire, selon le côté du =. 

const t = element.textContent;      ← LIRE
element.textContent = "Nouveau";    ← ÉCRIRE

C'est la même propriété. À gauche du = elle reçoit, à droite elle donne. Oublier le = est l'erreur la plus fréquente : le texte ne change pas, et rien ne le signale.

3 · .classList — ajouter et retirer des classes

Une classe CSS, c'est une apparence déjà écrite dans votre feuille de style. classList permet de la poser ou de la retirer :

InstructionEffet
el.classList.add("dispo")ajoute la classe
el.classList.remove("dispo")la retire
el.classList.contains("dispo")répond true ou false
el.classList.toggle("dispo")l'ajoute si absente, la retire si présente
Au départ :   class="badge"

el.classList.add("dispo")       → class="badge dispo"
el.classList.contains("dispo")  → true
el.classList.remove("dispo")    → class="badge"

toggle rend une valeur utile : true si la classe vient d'être ajoutée, false si elle vient d'être retirée. Deux appels de suite ramènent donc au point de départ.

Les noms de classes s'écrivent SANS le point. classList.add("dispo"), jamais classList.add(".dispo") — le point appartient au sélecteur, pas au nom.

Lire toutes les classes d'un coup : .className

classList sert à agir. Pour simplement voir où l'on en est, .className rend toutes les classes en un seul texte : 

el.className        → "badge dispo"

Pratique pour vérifier son travail dans la console. L'exercice 1 ne l'exigeait pas ; ici, deux critères le demandent, parce qu'afficher l'état des classes est le meilleur moyen de constater qu'on les a bien posées.

4 · .style — écrire une propriété à la main

el.style.backgroundColor = "gold";
el.style.color = "black";

Cela écrit un attribut style directement sur la balise, exactement comme si vous aviez tapé <p style="background-color: gold;"> dans le HTML.

En CSSEn JavaScript
background-colorbackgroundColor
font-sizefontSize
colorcolor

Le tiret disparaît, la lettre suivante prend une majuscule. C'est le camelCase des noms de variables, vu au projet 6 : un tiret n'est pas autorisé dans un nom de propriété JavaScript.

5 · ⚠️ Pourquoi préférer la classe au style

Ce n'est pas une préférence d'école. Un style écrit en ligne écrase ce que dit votre feuille CSS, et le neutralise : 

<p class="badge dispo">        ← la classe dispo met un fond vert

el.style.backgroundColor = "black";
→ le fond devient NOIR : la classe est toujours là, mais elle ne
  s'applique plus.

el.style.backgroundColor = "";
→ le fond redevient VERT : la classe reprend la main.

Tant que le style en ligne est posé, la classe est sans effet. Et pour revenir en arrière, il faut le vider explicitement — une chaîne vide — ce qu'on oublie presque toujours.

classList.style
Où est décrite l'apparence dans le fichier CSS éparpillée dans le JavaScript
Pour changer une couleur on modifie le CSS on cherche dans le code
Revenir en arrière remove() réaffecter ""
Quand l'utiliser presque toujours valeur calculée (une largeur, une position)

Vous avez déjà entendu cet argument. Au projet 3, la balise <style> dans la page était présentée comme un dépannage ou une contrainte technique, jamais comme la façon normale de travailler. .style en JavaScript, c'est la même chose : possible, parfois utile, rarement souhaitable.

6 · Lire un nombre caché dans un texte

Une page affiche rarement un nombre nu. Elle écrit 712 pages — du texte, dont seul le début est un nombre.

Number() ne s'en sort pas : il exige que tout le texte soit un nombre. 

Number("712 pages")    → NaN     ⚠️

On découpe donc le texte avant de convertir. .split(" ") coupe à chaque espace et rend un tableau — celui du projet 8 : 

"712 pages".split(" ")        → ["712", "pages"]
"712 pages".split(" ")[0]     → "712"        ← la première case
Number("712 pages".split(" ")[0])  → 712     ✅

Et sur un texte lu dans la page, ce qui est le cas réel : 

const texte = livre.querySelector(".livre__pages").textContent;   ← "712 pages"
Number(texte.split(" ")[0])                                        → 712

Rien de neuf sur le fond : un tableau, un index à partir de zéro, et Number() du projet 6. Seul .split() est nouveau — retenez-le tel quel, il vous resservira.

7 · Modifier plusieurs éléments d'un coup

Rien de neuf : on combine l'exercice 1 et la boucle du projet 8. 

for (const livre of document.querySelectorAll(".livre")) {
  livre.classList.add("lu");
}

Une erreur classique : appeler classList sur la liste au lieu de chaque élément. 

const livres = document.querySelectorAll(".livre");
livres.classList.add("lu");
→ TypeError: livres.classList is undefined

Une NodeList n'a pas de classes — ses éléments en ont. Il faut donc la parcourir.
