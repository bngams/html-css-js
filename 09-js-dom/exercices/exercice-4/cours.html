Projet 9 · Exercice 4

Une page qui se construit seule

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez faire ici : assembler les trois exercices précédents en un seul geste — vider, construire, relire.

Aucune notion nouvelle. Ce cours ne vous apprend rien : il remet en ordre ce que vous savez déjà, et montre dans quel ordre l'écrire.

1 · Le schéma complet

Une page pilotée par des données suit presque toujours les mêmes quatre temps : 

1. VIDER      retirer ce qui était écrit à la main
2. CONSTRUIRE fabriquer un élément par donnée
3. RELIRE     interroger la page qu'on vient d'écrire
4. RÉSUMER    afficher une synthèse

C'est le squelette de presque toute application web. Un catalogue, un panier, une liste de messages : même schéma, mêmes gestes. Ce que vous écrivez aujourd'hui, vous le réécrirez toute votre vie de développeur.

2 · Vider — l'étape qu'on oublie

Une page réelle contient souvent déjà quelque chose : un exemple laissé par l'intégrateur, un message d'attente, d'anciennes lignes. Si vous ne faites pas le ménage, votre contenu s'ajoute au lieu de remplacer. 

for (const ancien of liste.querySelectorAll("li")) {
  ancien.remove();
}

Bouclez sur querySelectorAll, jamais sur .children. C'est la règle de l'exercice 3, section 3 bis : .children est une liste vivante, qui se modifie pendant qu'on la parcourt. Elle sert à compter, pas à supprimer.

3 · Construire — un élément par donnée

Le geste de l'exercice 3, sans changement : fabriquer, remplir, insérer — le tout dans la boucle. 

for (const emprunt of emprunts) {
  const li = document.createElement("li");
  li.classList.add("emprunt");

  const titre = document.createElement("span");
  titre.textContent = emprunt.titre;

  li.append(titre);
  liste.append(li);
}

Une carte porte souvent plusieurs informations. Un <span> par information, chacun avec sa classe : c'est le CSS qui décidera ensuite de leur place. Votre code décrit ce que c'est, pas où ça va.

4 · Compter pendant qu'on construit

L'accumulateur du projet 8 se glisse naturellement dans la boucle de construction : une seule traversée suffit pour bâtir et compter. 

let enRetard = 0;

for (const emprunt of emprunts) {
  // … construction …

  if (emprunt.jours > 28) {
    li.classList.add("retard");
    enRetard = enRetard + 1;
  }
}

Poser la classe et incrémenter au même endroit garantit que le compte et l'affichage ne peuvent pas diverger. Deux boucles séparées, et un jour l'une des deux oublie un cas.

5 · Relire la page qu'on vient d'écrire

Une fois insérés, vos éléments sont des éléments comme les autres : querySelectorAll les retrouve, textContent les lit. 

for (const ligne of liste.querySelectorAll(".emprunt__jours")) {
  totalJours = totalJours + Number(ligne.textContent.split(" ")[0]);
}

Le texte de la page n'est pas un nombre. "30 jours" doit être découpé avant d'être converti — c'est le .split(" ")[0] de l'exercice 2, section 6. 

Number("30 jours")                  → NaN   ⚠️
Number("30 jours".split(" ")[0])    → 30    ✅

Pourquoi relire la page plutôt que les données ? Ici, les deux donnent le même total — c'est d'ailleurs une bonne vérification. Mais quand la page aura été modifiée après sa construction (projet 10), seule la page dira la vérité.

6 · Résumer

La synthèse n'est qu'un textContent et un classList de plus — ceux de l'exercice 2 : 

bandeau.textContent = emprunts.length + " emprunts, dont " + enRetard + " en retard";

if (enRetard > 0) {
  bandeau.classList.add("alerte");
}

La classe porte l'apparence, le code porte la décision. Le JavaScript dit « il y a des retards » ; le CSS décide que cela s'affiche en rouge. C'est la règle de l'exercice 2, section 5 — et la raison pour laquelle on évite .style.

7 · L'ordre compte

Si vous…Alors…
construisez avant de vider le ménage efface aussi vos propres lignes
affichez le compte dans la boucle vous lisez un total intermédiaire, jamais le total final
relisez la page avant de l'avoir construite vous obtenez 0, sans erreur

Aucun de ces trois cas ne produit d'erreur rouge. Le code tourne, le résultat est faux. C'est pourquoi les affichages console de l'énoncé sont placés à des moments précis : ils sont là pour détecter ces inversions.
