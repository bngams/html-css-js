🎯 Objectif — Désigner des éléments de la page depuis JavaScript, lire ce qu'ils contiennent, et mettre un compteur à jour.

Prérequis : le projet 6 (querySelector, textContent, la balise <script> en bas) et le projet 8 (for…of).

⚠️ Le format change à partir d'ici. Plus de marqueurs // TODO: à remplacer un par un : votre fichier est presque vide.

Ci-dessous, un objectif et des critères d'acceptation — ce que votre code doit produire. Comment y arriver vous appartient. C'est déroutant cinq minutes, et c'est ainsi qu'on travaille vraiment.

Un seul fichier : exercices/exercice-1/app.js

✅ Les critères d'acceptation

Votre code doit produire exactement ces effets. L'ordre des lignes compte.

Dans la console

  1. Le texte du titre de la page, précédé de Titre :
  2. Le titre du premier livre seulement, précédé de Premier livre : — en utilisant la méthode qui rend un seul élément
  3. Le nombre total de livres, précédé de Nombre de livres :
  4. Le nombre de livres disponibles, précédé de Disponibles :
  5. Le nombre de livres de classe perdu — qui n'existe pas dans la page — précédé de Perdus :, suivi de · est-ce null ? et du résultat de la comparaison à null
  6. Une ligne par livre : ·, son titre, —, son auteur

Dans la page

  1. Le paragraphe #compteur doit afficher 5 livres au catalogue, dont 3 disponibles — avec les nombres calculés, jamais écrits à la main

Le critère 5 est le plus instructif. Il vous fait constater la différence entre les deux méthodes de recherche : l'une rend null quand elle ne trouve rien, l'autre une liste vide. Ce n'est pas la même chose, et cela change la façon de s'en servir.

Pourquoi chercher ce qui n'existe pas ? Parce que cela arrive tout le temps en vrai : un catalogue vide, un filtre sans résultat, une page pas encore chargée. Votre code doit tenir sans planter — et c'est querySelectorAll qui vous le garantit.

🔍 Comment vérifier

Décompte : avec la solution proposée, six affichages produisent dix lignes — le critère 6 est une boucle sur cinq livres.

Si votre chemin diffère, votre décompte aussi : ce sont les critères d'acceptation qui font foi, pas le nombre d'instructions.

Le singulier Le critère 2 donne un seul titre, alors que cinq livres portent la classe

Rien n'est écrit en dur Ni 5 ni 3 ne figurent en clair dans votre code : ils viennent de .length

🧪 Manip — une NodeList n'est pas un tableau

Dans la console de la page de travail, tapez :

  1. const l = document.querySelectorAll(".livre")
  2. l.length → 5, comme un tableau
  3. Array.isArray(l) → false ⚠️
  4. l.map → undefined ⚠️ la méthode n'existe pas
  5. Array.from(l).map(e => e.textContent) → là, ça marche

Elle a un .length, des index, un .forEach, et for…of la parcourt — mais ce n'est pas un tableau. Retenez-le : la surprise vient toujours au mauvais moment.

🏁 Comment savoir que j'ai fini

  • Les dix lignes s'affichent, dans l'ordre, sans erreur rouge
  • Le compteur de la page est à jour
  • Vous savez dire ce que rend chaque méthode quand elle ne trouve rien
  • Aucun nombre n'est écrit en dur dans votre code
