Trouver dans la page

Ce que vous allez apprendre ici : désigner un élément de la page depuis JavaScript — un seul, ou plusieurs — et comprendre ce que vous recevez en retour.

1 · Le DOM, ou la page vue par JavaScript

Quand le navigateur lit votre HTML, il n'en garde pas le texte : il en construit une représentation en mémoire, faite d'objets imbriqués. C'est le DOM — Document Object Model.

Dans le fichierDans le DOM
<h1>Bonjour</h1>un objet, avec des propriétés
du textedes objets que le code peut lire et modifier

Vous en avez déjà vu un morceau au projet 6 : document.querySelector("h1"). document est le point d'entrée — la page entière. Tout part de là.

2 · querySelector — le premier qui correspond

document.querySelector("h1")        → l'élément <h1>
document.querySelector(".item")     → le PREMIER élément de classe item
document.querySelector("#total")    → l'élément d'identifiant total

Les sélecteurs sont exactement ceux du CSS. Le projet 3 vous a donné les trois de base — la balise, la classe, l'identifiant. En voici deux autres, dont vous aurez besoin ici :

SélecteurDésigne
.livre tous les éléments de classe livre
.livre.disponible
collés, sans espace		 ceux qui ont les deux classes à la fois
.livre .titre
séparés par un espace		 un .titre situé à l'intérieur d'un .livre

L'espace change tout. .livre.disponible cherche un seul élément portant les deux classes ; .livre .disponible cherche un élément contenu dans un autre. Une espace de trop, et la recherche ne trouve plus rien — sans erreur.

« querySelector », au singulier : il rend UN seul élément — le premier trouvé dans l'ordre du document, même si dix autres correspondent.

Et s'il ne trouve rien, il rend null — sans erreur. Vous connaissez la suite depuis le projet 6 : écrire dans ce null déclenche un TypeError.

3 · querySelectorAll — tous ceux qui correspondent

document.querySelectorAll(".item")    → les TROIS éléments
querySelectorquerySelectorAll
Rend un élément une NodeList
Si rien ne correspond null une liste vide (length vaut 0)
On l'utilise pour agir sur un seul agir sur chacun

La différence du cas « rien trouvé » compte. Avec querySelectorAll, pas de null : on reçoit une liste vide, qu'on peut parcourir sans risque — la boucle ne fait simplement aucun tour.

4 · ⚠️ Une NodeList n'est pas un tableau

Elle y ressemble beaucoup — elle a un .length, des index, et se parcourt avec for…of. Mais : 

Array.isArray(liste)    → false      ⚠️
liste.map(…)            → undefined  ⚠️ la méthode n'existe pas
liste.filter(…)         → undefined  ⚠️
liste.forEach(…)        → ✅ celle-ci existe

Si vous avez besoin des outils d'un vrai tableau, on convertit : 

Array.from(liste)       → un vrai tableau

Pour cet exercice, for…of suffit — celui du projet 8, inchangé : 

for (const item of document.querySelectorAll(".item")) {
  console.log(item.textContent);
}

5 · Lire ce qu'on a trouvé

PropriétéDonne
.textContentle texte, sans les balises
.innerHTMLle contenu avec les balises
.tagNamele nom de la balise, en majuscules
.classNameses classes, en un seul texte
.idson identifiant

Sur <p id="cible">Texte <strong>gras</strong> ici</p> :

.textContent    → "Texte gras ici"
.innerHTML      → "Texte <strong>gras</strong> ici"

.textContent vous donne ce que lit le visiteur ; .innerHTML ce qu'a écrit le développeur.

Ce n'est pas au programme d'aujourd'hui — aucun critère ne demande innerHTML, .tagName ni .className. Retenez .textContent ; l'exercice 2 reviendra sur le choix entre les deux.

6 · Ce qu'une librairie remplace

Vous entendrez parler de jQuery, une librairie très répandue. Voici la même action, dans les deux écritures :

Avec jQueryEn JavaScript natif
$(".logo") document.querySelectorAll(".logo")
$("#total") document.querySelector("#total")

C'est plus court — et c'est tout. jQuery ne fait rien que le navigateur ne sache faire : il abrège. À l'époque où les navigateurs se comportaient différemment, il rendait de grands services ; aujourd'hui, le natif suffit dans la plupart des cas.

Apprendre le geste avant le raccourci vous permettra de lire les deux. Nous reverrons jQuery en fin de journée, quand vous saurez ce qu'il remplace.

Une nuance, si vous lisez du jQuery : il rend toujours une collection, même pour un identifiant. $("#total") contient un élément ; pour l'élément lui-même, on écrit $("#total")[0]. C'est ce qui explique qu'un $("#total").textContent ne donne rien.

7 · Rappel : où placer le script

Tout ceci ne fonctionne que si votre script est en bas du <body> — la leçon du projet 6, exercice 4. Placé dans le <head>, il s'exécute avant que les éléments existent, et querySelector rend null.

Dans tous les exercices de ce projet, la balise est déjà au bon endroit.
