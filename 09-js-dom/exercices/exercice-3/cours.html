Projet 9 · Exercice 3

Créer et insérer

  • 📖 Cours
  • 📋 Énoncé
  • ✍️ À vous de jouer
  • ✅ Solution

Ce que vous allez apprendre ici : fabriquer des éléments qui n'existaient pas dans le HTML, et les placer dans la page.

1 · Du contenu qui n'est pas écrit à la main

Jusqu'ici, les éléments étaient déjà là : vous les trouviez, vous les modifiiez. Mais un catalogue de trois cents livres ne s'écrit pas à la main dans le HTML — il arrive sous forme de données, et c'est le code qui construit la page.

Vous savez déjà décrire ces données. C'est le tableau d'objets du projet 8 : 

const catalogue = [
  { titre: "Dune", pages: 900 },
  { titre: "La Horde", pages: 712 }
];

Il ne manque que le geste pour les transformer en éléments.

2 · createElement — fabriquer

const li = document.createElement("li");

L'élément existe, mais il n'est nulle part. Il est fabriqué en mémoire, pas dans la page : 

li.tagName           → "LI"        ✅ c'est bien un élément
li.textContent       → ""          vide au départ
li.parentElement     → null        ⚠️ il n'a pas de parent
document.body.contains(li)  → false  ⚠️ invisible

Rien ne s'affiche tant qu'on ne l'a pas inséré. C'est la cause numéro un du « mon code tourne mais je ne vois rien » sur ce chapitre.

On le remplit comme n'importe quel élément trouvé :

li.textContent = "Dune";
li.classList.add("livre");

Rien de neuf : .textContent et .classList sont ceux de l'exercice 2. Un élément fabriqué se manipule exactement comme un élément trouvé.

3 · append — insérer

document.querySelector("#liste").append(li);
InstructionPlace l'élément
parent.append(el)en dernier dans le parent
parent.prepend(el)en premier
el.remove()le retire de la page
Avant :  <ul> Un · Deux </ul>

liste.append(trois)   → Un · Deux · Trois
liste.prepend(zero)   → Zéro · Un · Deux · Trois

append accepte plusieurs éléments à la fois : parent.append(a, b, c). Il accepte même du texte brut — parent.append("bonjour") — mais celui-ci n'est alors pas un élément : on ne peut ni lui donner de classe, ni le retrouver avec querySelector.

3 bis · Compter ce qu'il y a dans un parent

Une fois des éléments insérés, on veut souvent savoir combien il y en a. Un parent sait le dire, sans qu'on ait à écrire de sélecteur : 

liste.children          → ses éléments enfants
liste.children.length   → combien il y en a

La différence avec querySelectorAll de l'exercice 1 tient en un mot : directs. 

<ul id="liste">
  <li>A <span>dedans</span></li>
  <li>B</li>
</ul>

liste.children.length              → 2   les deux <li>, rien d'autre
liste.querySelectorAll("*").length → 3   les <li> ET le <span> dedans

querySelectorAll descend à tous les niveaux ; .children s'arrête au premier. Pour compter les lignes d'une liste, c'est exactement ce qu'il faut.

Ne supprimez jamais en bouclant sur .children. Cette liste est vivante : elle se met à jour pendant que vous la parcourez, et la boucle en saute la moitié. 

boucle sur querySelectorAll("li") + remove()  → 5 tours, il reste 0   ✅
boucle sur children              + remove()  → 3 tours, il reste 2   ❌

C'est pourquoi le ménage de la section 7 s'écrit avec querySelectorAll. .children sert à compter, pas à supprimer.

4 · ⚠️ Insérer un élément déjà placé le DÉPLACE

Le piège le plus surprenant de ce chapitre. append ne fait pas de copie : si l'élément est déjà quelque part dans la page, il est retiré de son ancien emplacement. 

Liste A :  Zéro · Un · Deux
autreEndroit.append(zero);

Liste A :  Un · Deux          ⚠️ Zéro a DISPARU de la liste A
autreEndroit :  Zéro          il a été déplacé, pas dupliqué

Un élément n'existe qu'à un seul endroit à la fois. Pour en avoir deux, il faut en fabriquer deux — c'est justement ce que fait une boucle.

5 · Construire un élément qui en contient d'autres

Une ligne de catalogue n'est pas un simple texte : c'est un <li> qui contient un titre et un nombre de pages. On assemble, puis on insère le tout : 

const li = document.createElement("li");
li.classList.add("livre");

const titre = document.createElement("span");
titre.textContent = "Dune";
li.append(titre);

liste.append(li);

Ce qui produit, dans la page :

<li class="livre"><span>Dune</span></li>

L'ordre a une logique : on fabrique de l'intérieur vers l'extérieur, et on n'insère dans la page qu'à la fin. Tant que li n'est pas inséré, on peut le remplir tranquillement — rien ne s'affiche encore.

6 · La boucle qui construit

Assemblez ce que vous savez : un tableau d'objets du projet 8, une boucle for…of, et le geste ci-dessus. 

for (const livre of catalogue) {
  const li = document.createElement("li");
  li.textContent = livre.titre;
  liste.append(li);
}

Le createElement doit être DANS la boucle. Placé avant, il ne fabrique qu'un seul élément — et comme append déplace au lieu de copier, vous obtiendrez une seule ligne, portant le dernier titre.

C'est la conséquence directe de la section 4. Un tour de boucle, un élément neuf.

7 · Vider avant de reconstruire

Si la page contient déjà des éléments et que vous voulez les remplacer, il faut d'abord faire le ménage : 

for (const ancien of liste.querySelectorAll("li")) {
  ancien.remove();
}

Sans cela, vos nouvelles lignes s'ajoutent aux anciennes — append ne remplace rien, il complète.

8 · Et innerHTML ?

Vous verrez souvent, ailleurs, une liste construite par assemblage de texte : 

liste.innerHTML += "<li>" + livre.titre + "</li>";

Ce n'est pas au programme de ce cours, et ce n'est pas un oubli. Cette écriture recolle toute la page à chaque tour, perd ce qu'on avait déjà posé, et — si le titre vient d'un visiteur — laisse insérer du code dans votre page.

createElement n'a aucun de ces défauts. C'est un peu plus long à écrire, et c'est ce qu'on écrit.
